first hour ([`the-midwife.md`](./the-midwife.md) §2.1, over `life-signal.md` §3,
the maintenance axis)? The read is the field's own — deterministic, legible,
never a seeded vitality roll. This read is what the baptism binds:

> **[design] The baptism binds the *received* fresh run — the run whose first
> state was read and whose first line was booked.** It does not bind an
> un-received run (a fresh line nobody took in has no first read, no first line
> — there is nothing for the name to bind to the midwife's ledger with), and it
> does not bind a run that reads failing and is not held (the-name's honest
> bound — a name cannot bind what the field does not hold,
> [`the-name.md`](./the-name.md) §2). The baptism's subject is exactly
> `the-midwife.md` §1's received run: the one whose first hour was held — read,

## 3. The received run made bound — the load-bearing design

### 3.1 The baptism is the midwife's receiving made a name

> **[design] The first-naming is the midwife's receiving made a name — the first

### 3.2 What the received run gains — named, not merely kept

> **[design] The honest gain is legibility, never a grant.** The baptism gives

> legibility ([`the-name.md`](./the-name.md) §1/§3): the name holds the structure
