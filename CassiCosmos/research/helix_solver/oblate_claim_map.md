# Oblate Bubble — Claim Map across the workspace

Companion to `oblate_provenance_audit.md` (commit `27ad20f`), which established that σ_x/σ_y = 1.422 and σ_x/σ_z = 2.510 are single-run Python-PDE outputs from `CassiTheory/visual-explainers/string_bubble_cascade.py`, NOT Godot-engine measurements, and that the engine ships no bubble-shape readout. This document maps **every claim site** into one of four buckets:

- **ENGINE-CLAIM** — asserts the running engine/sim itself produces the oblate shape (a mechanism is owed).
- **ILLUSTRATIVE** — visual-explainer / analytic construction; no engine or measurement grounding.
- **THEORY-PREDICTION** — doctrine predicts the shape as physics (reference only; not engine-observed).
- **UNVERIFIED-QUOTE** — cites the 1.422/2.510 numbers (or an equivalent shape "record") with no engine grounding, usually presenting a Python-PDE output as if it were a confirmed record.

**Read-only survey** — root doc (`UNIFICATION.md`) was never edited; the only new file is this one.

## 2. Verdict paragraph

**There is NO document in the workspace that asserts the running Godot engine or sim produces the oblate/ellipsoidal bubble as a measured physics record — the mechanism is not owed by any engine claim, because none exists.** Every occurrence of the oblate shape falls into one of three buckets: (i) **THEORY-PREDICTION** — doctrine prose predicting the shape (`CassiTheory/README.md:31`, `cassi-physics.md:27`, `bubble-edge-geometry.md:112`, `bubble-lattice-fabric.md:65`, `chakras-as-cascade-bubbles.md:178-180`, cosmology `desi-lattice-averaging.md`/`observational_constraints.md`/`run_cmb_lowl_pipeline.py`, and the box rationale in `GRID_LAYOUT.md:79-82`); (ii) **ILLUSTRATIVE** — visual-explainers, the numpy PDE `string_bubble_cascade.py`, and the `triaxial3d*` analytic probe machinery, all of which either seed the geometry or measure a chosen operator aspect rather than the engine; or (iii) **UNVERIFIED-QUOTE** — every reference to the 1.422/2.510 numbers, which traces to the Python script and is treated in the `helix_solver` suite as "reference lines, not gates," several of which explicitly label 2.510 as "NOT an engine measurement" / "unverified Python-PDE" (`triaxial3d_feed_prereg.md:34-38,197,267-268`; `triaxial3d_feed_probe.py:258`). Crucially, the strongest negative evidence comes from the `triaxial3d_simop_corr` and `triaxial3d_feed` waves: the sim's **actual** (φ,1,φ²) operator was measured to yield a **PROLATE** (z-stretched) bubble (σ_x/σ_z = 0.329), and the wave-9 feed/source-gravity mechanisms all returned **CONTRADICTS / DOES NOT EMERGE** — the corpus's own verdict is that the oblate 2.510 "if it is real — must live in a sector this scalar-field probe line cannot yet capture" (`triaxial3d_feed_report.md:105-115`).

**Which docs would need a dated provenance note:** the single document most in need is `CassiTheory/foundations/bubble-edge-geometry.md:11` — it is the only doctrine-adjacent site that presents the exact σ ratios under the phrase **"φ-ellipsoid bubble confirmed"**, which reads as an established (near-engine) measurement record even though it grounds to the Python script; a reader could mistake it for engine-observed physics. A dated note there (and, secondarily, at the three `helix_solver` pre-registration/report cites that still call the Python output "the sim record" or "recorded measurements" — `triaxial_prereg.md:90-91`, `triaxial3d_relax_prereg.md:21`, `triaxial3d_report.md:106`, `triaxial3d_relax_probe.py:41`) should clarify that these are unverified, single-run Python-PDE reference lines, not engine measurements. The doctrine prose sites (`README.md`, `cassi-physics.md`, `bubble-lattice-fabric.md`, `chakras-as-cascade-bubbles.md`, cosmology) are predictions/illustrations and do not need a provenance correction, since they assert no engine basis. **Bottom line:** the wave-9/Wave-10 mechanism hunt is NOT repaying a debt owed by an engine claim — it tests an open, explicitly unverified reference, and no current doc incorrectly attributes the oblate shape to the engine.
