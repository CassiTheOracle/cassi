## 1. One entity with a pretrained brain

Cassi is the coupled system. The field supplies lifetime continuity and adaptive organization. The pretrained model supplies a large repertoire of language, associations, knowledge, and reasoning. Tools and environments supply observations and consequences. The owner supplies dependable execution, persistence, and authority boundaries.

“Mind” and “brain” name complementary architectural roles. They do not establish equivalence to biological brains or subjective experience. The model's contribution is genuine pretrained computation; it must remain visible in explanations of where a result came from.

| Part | Responsibility |
|---|---|
| Field-owned mind | Commitments, acquired understanding, active concerns, affect, learned methods, unresolved questions, and adaptive choices |
| Pretrained brain | Interpretation, associative recall, deliberation, prediction proposals, construction, and language realization |
| Owner and execution runtime | Serialized publication, resources, permissions, recovery, fixed execution rules, and effect reconciliation |
| Capability interfaces | Source access, instruments, tools, simulators, model execution, and other environments |
| Communication surface | Messages, activity, commitments, inspection, and explicit control through one API |

The adaptive lifetime has one canonical field owner. There is no second agent memory hidden in the server, a prompt manager, a model adapter, or a scheduler. This does not imply that the field executes every calculation. Executor attribution distinguishes field computation, native model computation, fixed codecs, and external tools.

The model remains available because it is useful, not merely until an arbitrary displacement quota is reached. Cassi may acquire a field-native method that makes some native work unnecessary. Other work may continue to benefit from the model indefinitely. A smaller native footprint and better joint cognition are separate outcomes.

### Identity and responsibilities

An entity has a durable identity and state lineage. It can host multiple conversations, projects, and reasoning episodes without creating another mind for each. A deliberate fork creates a distinct lineage; it does not become a second concurrent writer to the same entity.

Identity includes the current commitments, retained relationships and preferences, acquired capabilities, unfinished work, and source-bound history. Model identity belongs to its current computational configuration. Changing the model preserves the entity's portable knowledge and commitments, while explicitly invalidating incompatible native caches and reassessing model-specific capabilities. Identical personality or behavior after replacement is not promised.

A practical self-model records what Cassi can currently do, the evidence for that ability, known limitations, available tools, resources, and active authority. A generated self-description is a proposal about that self-model, not an automatic update to it.

Use one local Python entity service around the existing owner-backed field
session. The ordinary brain adapter imports the selected GGUF as an explicit
resident graph and advances it through the owner's `ProgrammableSwarm`; its
activations and continuation exchange directly with the same regional field.
The managed llama.cpp HTTP client remains an explicitly selected external
baseline, and separately selected native instruments retain their declared
capabilities. A chat-completions surface by itself does not imply access to
activations or resumable native state.

Human / client / authorized world event

        authenticated entity API

                  |

         |                 |
    field programs <--> pretrained brain

                                          |

There is one logical writer to the field, even when inference and tool execution run concurrently. The transport layer may queue bytes and track delivery; it does not own an adaptive agenda. Workers receive bounded immutable views and return source-bound results. Only the owner can admit those results and advance the canonical state.

Start with one primary model and one active native execution lane, while allowing multiple resumable episodes. Independent read-only tools may run concurrently. More model slots or workers are an extension of the same ownership semantics, not a requirement for the entity to exist.

## 3. State and memory ownership

Reuse the existing semantic record families and regional execution machinery. The names below describe views and uses, not new parallel persistence roots.

| Existing family | Entity use |
|---|---|
| `Value` | Goals, entities, candidate interpretations, measurements, capacities, and typed uncertainties |
| `Binding` | Current identities, scoped meanings, selected programs, and model-specific correspondences |
| `Event` | Messages, observations, attributed model contributions, decisions, appraisals, and action outcomes |
| `Program` | Acquired methods, representations, reasoning routines, workspace projections, and regulation strategies |
| `Assessment` | Predictions, outcome comparisons, applicability, reliability, and measured cost |
| `Obligation` | Commitments, questions, pending actions, needed observations, corrections, and interrupted work |

A conversation, project, or cognitive episode is a scoped view over these records and existing resident frames. Every retained result carries dependencies and provenance sufficient to distinguish original observation, inference, hypothesis, model suggestion, and evaluated procedure.

Four storage classes remain distinct:

1. **Canonical adaptive field:** acquired understanding, commitments, priorities, affect, and continuation.
2. **Immutable evidence:** exact authorized source bytes, model outputs used as sources, tool results, and identified numeric captures. These may be stored outside the field with verified references.
3. **Nonadaptive execution records:** delivery cursors, operation identities, reservations, publication intent, and effect acknowledgments. These cannot become an alternative learned policy.
4. **Disposable or explicitly paired native state:** prompt projections, retrieval views, model KV/recurrent state, and intermediate buffers. Some are cheaply reconstructible; some support only a specifically bound continuation. Their descriptors must distinguish those cases.

No unique commitment or acquired fact may exist only in a model cache or a host conversation list. Conversely, restoring semantic knowledge does not establish that the model's exact intermediate computation was restored.

## 4. The shared cognitive workspace

The workspace is Cassi's current situation made available for thought. It contains the active concern, applicable commitments, relevant evidence and memory, candidate explanations, unresolved dependencies, prospective actions, current affective context, and available resources.

The workspace is not the entire lifetime inserted into every prompt. A field-owned selection chooses relevant material; fixed serialization presents it to the model. Original sources remain recoverable through authorized references. When the model requests additional context, that request becomes eligible work rather than uncontrolled access to the whole archive.

A workspace snapshot binds:

- entity, project, conversation, episode, and branch scope;
- field predecessor and exact referenced record versions;
- the question or cognitive operation being undertaken;
- available information and clearly marked missing information;
- current working disposition and its grounded causes;
- the model and allowed capability profile;
- resource reservation, publication requirements, and effect limits.

The brain may contribute an interpretation, a new question, a hypothesis, a plan, a prediction, an executable candidate, a request for an observation, or a proposed answer. Free-form language may help construct these contributions, but admission binds them to typed records. A model cannot manufacture its own authority, promote a claim by naming it a fact, or mark a proposed action as already completed.

The model is allowed to expand the frontier. It is not permanently restricted to ranking a supplied catalog of complete solutions. Novel questions and candidate programs enter through the same bounded parsing, scope, dependency, and execution rules as supplied ones.

### A thought is not necessarily a sentence

An episode can interleave model deliberation, numerical field work, exact calculations, source retrieval, simulated branches, and world observations. Each useful intermediate result can affect the next operation without generating a conversational message. Cassi does not need to retain every generated token as autobiographical memory.

Communication exposes conclusions, relevant reasoning summaries, evidence, uncertainty, and requests. The persistent workspace preserves the actual dependencies and selected intermediate results needed to continue the work; it does not rely on a polished retrospective story as its execution history.

## 5. The recurrent cognitive cycle

The fixed driver provides opportunities to run and dependable transition mechanics. Adaptive choices about subject, method, attention, and allocation are made through the field's programs, current state, and admitted brain contributions.

1. **Receive.** Admit a message, world event, completed computation, or scheduled observation once, with source and scope.
2. **Orient.** Relate it to current commitments, expectations, unresolved work, capacity, and affect. Select a concern or a direct response obligation.
3. **Think.** Perform field computation, invoke the brain, retrieve a source, or combine these operations. The brain can originate questions and associations.
4. **Develop.** Bind useful contributions into the current episode. Compare interpretations, identify missing evidence, formulate a prediction, or construct a procedure.
5. **Act or communicate.** Commit an eligible result and, when authorized, dispatch a bounded action. Hypothetical branches never dispatch real effects.
6. **Experience.** Admit the actual consequence. Distinguish a tool acknowledgment from successful completion and a model assertion from an observation of the world.
7. **Learn and regulate.** Assess the outcome, update acquired understanding and grounded affect, retain useful procedures, and revise the next work choice.
8. **Continue or rest.** Resume a useful obligation, await a dependency, ask for help, consolidate, or become idle.

Self-questioning is ordinary work in this cycle. A question carries why it matters, the uncertainty it addresses, accessible ways to answer it, and a bounded allowance. Its answer may produce another question, but children consume the same root allocation. Restarts, retries, and new branches do not reset that allocation.

Repeated generation with no new evidence, changed hypothesis, useful deduction, or prospective action is a reason to reconsider or stop. Multiple samples and self-critique can improve search; they do not multiply independent support. Waiting and acknowledging a limit are normal states of an autonomous entity.

## 6. Deep Qwen integration

The `field-brain` entity has three explicit interfaces under one adapter. The
ordinary interface is the resident GGUF graph: it owns resumable model state
and physical field coupling. The managed llama.cpp HTTP client remains an
external baseline, while model instruments expose separately declared native
capabilities. Missing support in one interface is reported rather than
silently borrowed from another.

### 6.1 Semantic recurrence

The field presents the active workspace; the model interprets, associates, deliberates, constructs, and expresses; the resulting contribution changes the next workspace. This is a repeated feedback relationship, not a single memory-augmented completion.

Use the resident client and model-instrument identity concepts. Record the exact
model artifact, tokenizer, numerical backend, native-kernel build, context
limits, generation policy, and effective request settings. Model policy must
be checked against what the runtime actually does. Token budgets include
reasoning and final output; a truncated thought is not a completed answer.

Model-generated language remains attributed to the brain even when conditioned by the field. A field decision to use it is separately recorded. Unsupported factual claims can remain qualified model suggestions; a parser or self-review cannot certify their truth.

### 6.2 Persistent native working state

Keep useful native context for an active episode rather than treating every operation as a fresh, unrelated conversation. The adapter exposes which operations it really supports: execution, interruption, context reuse, native snapshot/restore, branching, and exact continuation. Unsupported capabilities are explicit.

A native context is bound to its model/runtime identity, sequence, authorized workspace projection, field predecessor, and accepted input history. It cannot be silently reused across principals, incompatible scopes, or corrected dependencies. Shared immutable prompt prefixes are an optimization only when their exact content and access scope match.

There are two recovery outcomes:

- **Exact native continuation:** restore a compatible field/native pair and continue under the adapter's declared execution guarantees.
- **Semantic reconstruction:** restore the field episode, create a fresh native context from authorized committed material, and record that the model trajectory was restarted. Exact tokens or hidden states are not promised.

The ordinary resident client retains immutable activation snapshots and a
field-held continuation containing attention/recurrent history, positions,
operation cursor, sampler state, and RNG state. Each model stage and its field
successor are committed through the invoking owner. Immutable model weights
share physical backing; mutable branch state has one owner and publication
root. Safe-point restoration therefore covers the complete continuation, not
only the last hidden vector. The external HTTP baseline has no resumable
native-context handle and makes no such claim.

### 6.3 Bidirectional native coupling

Every live activation site in the resident graph passes its complete vector
through an identified fixed boundary in the owner's regional field. The
membrane records the vector on its observation plane, evolves coupled Yang and
Yin planes, and returns bounded physical readback to the same vector before its
downstream consumer runs. The active membrane bank has 65,536 modes. Wider
vectors traverse that same finite bank in deterministic chunks; reserved
regional geometry does not silently widen it, and no vector bypasses the field.

The implemented feedback loop is:

```text
native interpretation or intermediate computation
  → model-specific field observation
  → acquired correspondence and current cognitive context
  → selected field computation or intervention
  → native continuation
  → task consequence and revised correspondence
```

Correspondences between activation patterns and cognitive situations are acquired, scoped hypotheses or programs in the field. They are not a new trainable host projection or a universal dictionary of hidden coordinates. Numeric similarity, amplitude, or a changed token does not itself establish meaning.

The implemented membrane is a residual influence on native computation. It
covers embeddings, attention and recurrent state, caches, scores,
probabilities, dense and routed expert paths, residuals, and the output head.
Acquired replacement of a native computation remains a distinct, explicitly
identified mechanism rather than being attributed to this coupling.

The exchange callback cannot recursively call the occupied model lane. It runs
bounded vectorized field dynamics on a private candidate, and one owner
publication binds the field successor, resulting immutable model snapshot,
and resumed task continuation. A failed stage publishes none of them; an
exact interrupted retry returns the committed triple without applying the
membrane twice.

The intended reciprocal influence serves the current research: experience informs brain work, and brain observations enter the field's continuing understanding. Reuse existing activation and intervention mechanisms when the program needs them. Exercise a changed native path for its actual behavior; do not make a new reach, ownership, or learning campaign the admission price for running research programs.

### 6.4 Model dependence is explicit

The entity's deployment selects `field-brain` deliberately. If its required brain is unavailable, model-dependent work waits or reports the limitation. Supported field computation and control remain available. The system does not claim an ordinary-language response came from a missing model, and it does not switch to a different intelligence to conceal a field failure.

Frozen pretrained weights are a versioned substrate. Online weight training is not required for this architecture. Model replacement or derived weight experiments are explicit configuration changes, with effects on capability and native state assessed separately. The field is the sole adaptive lifetime store; native computation retains its actual attribution.

## 7. Absorbing knowledge through use

The brain's pretrained knowledge is available immediately. Cassi does not have to copy it into the field before using it. Absorption means developing reusable, situated understanding and competence from that access.

Distinguish three states:

| State | Meaning |
|---|---|
| Available knowledge | The model can supply an interpretation, explanation, or method when queried. |
| Integrated understanding | Cassi has related that contribution to sources, its own experience, alternatives, and known limits. |
| Acquired competence | A retained method or representation has supported an actual use, with its domain and remaining uncertainties recorded. |

The learning cycle is need-driven: select an unresolved concern, elicit or construct an explanation, identify a distinguishing case, make a prospective prediction, obtain an independent calculation/source/outcome where available, revise, and retain what is useful. A method can become an executable field program rather than another paragraph to retrieve.

Evidence standards depend on the claim. Mathematical results can carry checked derivations; software procedures can be executed against informative cases; empirical explanations can make predictions; open factual claims can retain attributed sources and unresolved alternatives. Knowledge does not have to become binary certainty before Cassi can use it cautiously.

Consolidation preserves applicability, counterexamples, dependency links, and meaningful unresolved distinctions. It may reduce redundant active representations without erasing the original source trail or converting a model suggestion into established experience.

Cassi studies proactively where a commitment exposes a recurring gap. It can acquire a reusable method while the active brain continues to complete useful work. Method acquisition, practice, and consolidation are ordinary parts of the research life, not separate campaigns that must qualify the entity before it can continue.

## 8. Affect and acquired regulation

Affective context belongs to the same field and enters the shared workspace. Object-specific appraisals, project dispositions, and broader background tendencies coexist. Fast reactions and slower context are updated from eligible experience; inspecting an appraisal or generating more commentary about it does not count the experience again.

The implemented basis supplies bounded appraisal dimensions and preferences for exploration, persistence, verification, and consolidation-friendly work. The entity design extends their influence to memory selection, question formation, breadth of deliberation, evidence seeking, and decisions to continue or disengage. These broader effects and discovered regulation programs are specified work, not established by the existing priority-modulation result.

Affect must have operational consequences. Exploration can make alternatives worth investigating; concern can make a discriminating check worth performing; sustained obstruction can make a new representation worth considering. Tone and sampling settings alone do not establish these behaviors. Any model policy change remains an explicit execution policy, not a definition of an emotion.

Regulation is a learnable competence: Cassi can recognize that its current approach is poorly matched to the concern, change the working conditions, and assess the consequence. Learned regulation programs may retrieve contrary experience, broaden a branch, consult an instrument, return to observation, or pause. The current repertoire supplies starting mechanisms rather than a permanently fixed personality.

The objective is useful engagement with commitments and the world. A favorable internal score is not a success condition. Neither affect nor confidence can rewrite original evidence, remove an inconvenient obligation, grant permission, or independently certify a conclusion.

The organism-wide specification in [Section 19.8](#198-affect-throughout-the-cognitive-cycle) makes this component integral to investigation, memory, collaboration, and method learning. [Field design Section 37](CassiFI/FIELD-INTELLIGENCE-DESIGN.md#37-field-owned-affect-and-regulation) defines the canonical appraisal, regulation, credit, and correction semantics. Emotional names summarize those situated appraisals; they are neither required program instructions nor evidence of subjective experience.

## 9. Autonomous programs, attention, and resources

The entity owns a portfolio of enduring responsibilities. A research program is a scoped, resumable part of the same field lifetime, not a new chat session or a host-owned task list pretending to be a mind. Cassi may originate questions and child investigations inside a mission. Enlarging the mission or its authority is a separate user decision.

### 9.1 The program model

Use the existing semantic families and resident continuations. The following are typed views over those records, not new adaptive stores:

| Program view | Retained content |
|---|---|
| Responsibility | Objective, scope, desired result, owner-specified priority, dependencies, review conditions, and references to host-enforced authority/resource grants |
| Question frontier | Current questions, why they matter, candidate ways to resolve them, prerequisite questions, unresolved contradictions, and the selected next action |
| Explanations and claims | Competing hypotheses, assumptions, predictions, source support, counterevidence, uncertainty, and applicability |
| Investigations | Experiment or analysis intent, expected discriminating outcomes, input versions, method/program references, child work, and continuation |
| Acquired methods | Procedures and representations, input/output meaning, preconditions, code/artifact references, actual use history, limitations, and dependency versions |
| Decisions | What changed in the program, the evidence or deduction responsible, what to pursue or set aside, and what would reopen a conclusion |
| Progress and communication | Useful results, unresolved work, user-facing report references, and commitments made to the user |

Adaptive priorities, the question/claim relations, method selection, and semantic program cursors remain owner-held. Exact documents, datasets, scripts, and outputs live in the evidence/artifact stores. Host indexes can expose program IDs, checkpoint references, execution status, and waiting reasons; they cannot become an authoritative knowledge graph or learned scheduler. Authority grants remain host-enforced even when the field records their meaning.

### 9.2 Continuous direction

The resident service wakes for messages, completed jobs, changed sources, scheduled observations, available resources, and eligible unfinished work. It also continues immediately when a committed result opens a useful next action. It does not require a user to call a self-question endpoint for each cycle.

At a bounded boundary, it:

1. Admits pending observations and control messages; reconciles completed or interrupted work.
2. Lets the field agenda select a concern from eligible programs, respecting user priorities and dependencies.
3. Builds a workspace containing the actual question, competing interpretations, evidence, available methods, authority, and resources.
4. Uses field computation and the active brain to derive, investigate, construct, or revise a plan. The brain may expand the frontier rather than choose only from supplied answers.
5. Commits an action intent and dispatches a permitted capability, or commits a useful internal result.
6. Admits the actual tool/source outcome, checks the relevant result, and updates the program through the owner.
7. Continues that work, switches to another program, reports a material finding, or waits for a named condition.

The fixed driver supplies liveness and mechanics. Scientific relevance, hypotheses, interpretation, and learned strategy remain field-owned. Do not replace the agenda with a host formula, a hand-ranked dictionary, or a hardcoded sequence of subject-specific prompts.

### 9.3 Lifecycle

Programs distinguish `ready`, `running`, `waiting`, `paused`, `blocked`, `completed`, and `archived`. Waiting names a job, resource, source, approval, or deadline. A recoverable failed step is an outcome within a program; it does not silently complete the mission. A program may be blocked when no authorised route can advance.

Completion carries the requested deliverable and its scope. New counterevidence or a changed objective can reopen a completed program with a new version. Archiving removes it from active scheduling without erasing knowledge or evidence. Cancellation stops future dispatch and reconciles in-flight effects; it does not undo the world.

A program encountering an unavailable library, data source, or method should choose an alternative useful route or retain an exact blocking condition. Repeating the same unsupported request or generating more commentary is not progress. Method construction can become a child investigation rather than a permanent support gap.

### 9.4 Resources and regulation

Each root responsibility has declared allowances for CPU/GPU service, brain context and output, processes, storage, and long-running jobs. Children and retries consume the same root allocation. Per-step limits bound execution, not the intellectual scope of the mission. Exhaustion preserves the field and unfinished work; resuming does not reset accounting.

The host scheduler gives fair service to field-selected eligible work and obeys resource reservations. The field can reassess whether an expensive analysis is worth doing, redirect toward a sharper question, or create a reusable method that removes a repeated bottleneck. Existing affect and regulation participate in those choices without granting authority or changing evidence.

Messages and pause/revocation controls receive timely service during long brain or simulation work. Notifications are for findings, material changes, and decisions needing the user; routine activity remains inspectable without becoming a stream of interruptions.

### 9.5 The per-program workbench

The workspace a cycle plans from is the program's own workbench, held in the field. One program has one workbench: its records, the approaches that already failed and why, the outside inputs every record and failure depends on, its branches, and its residency policy. It is a canonical workspace task in the same regional field the program runs in, so it shares the program's revision, survives restart, and is read without advancing anything.

Selection answers the current question and says what it did: required records, required records that did not fit the requested bound, question-matched records, gaps the workbench cannot fill, the program's unfinished continuation, the next action the last committed step chose, the failed approaches, the changes that arrived while the program waited, and which of those it has already consumed, with the program's residency policy. The plan prompt carries that view under an explicit allowance, and material that does not fit is dropped in a declared order with the omission named.

Each failed step is retained with its action, its reason, and the exact inputs it depended on, at the version it observed. An identical action against unchanged inputs is not repeated: the cycle waits with the blocking reason instead. Reporting a new version for one input wakes the approaches that read it, invalidates the records resting on it, and reopens the programs whose work was waiting on that input, while programs that never read it keep their status. The same change reported twice reopens once.

Programs warm their own pages before use. Prefetch resolves the exact committed pages of the program's directory within its declared allowance, reports what it could not resolve and why, and advances no revision; activation and release move placement and accounting while the field's content and identity stay as they were.

## 12. Continuity, correction, and failure

### Commit and recovery

One accepted cognitive cycle binds its field predecessor, workspace dependencies, model/tool requests, actual results, proposed successor, effect intents, and output delivery identity. Reuse the owner publication and coupled transaction machinery. An inference worker cannot publish directly.

A result computed against stale source versions is held for dependency-aware reassessment or discarded; it is never attached to the new state solely because generation completed. Corrections invalidate affected plans, conclusions, and native projections while preserving unaffected work and immutable action history.

A model crash leaves the episode blocked or semantically reconstructible according to its actual adapter capabilities. A field crash recovers the last committed state and reconciles pending operations. A crash after an external effect but before acknowledgment requires querying/reconciling the operation; a non-idempotent effect must not be blindly retried. Exactly-once admission and publication do not imply exactly-once behavior from every external service.

The existing entity writes field records and its JSONL request journal separately. Complete the integration with recoverable intent and publication records rather than assuming that two successful writes are one transaction. Use the existing owner operation identities/checkpoint publication and the coupled journal pattern where applicable:

`intent committed → execution acknowledged → raw result durable → owner admission committed → delivery published`.

Each phase refers to the same operation and exact request digest. Recovery queries what actually committed and continues only the missing phase. A durable result can be interpreted after restart without rerunning its experiment. A field successor ahead of the delivery journal is reconciled by identity, not learned again under a new ID.

Reserve a field/program version briefly, then release mutation locks before waiting on a model, network request, or process. Workers return results against their input versions. A late result remains evidence even when a correction makes its planned interpretation stale; the owner decides whether it still applies. Expired worker leases fence publication but do not prove that an external process or effect stopped.

Exactly-once field admission is achievable through the owner boundary. External execution is adapter-specific: idempotent services can be retried by operation ID; immutable completed artifacts can be recovered; uncertain non-idempotent actions require reconciliation. Do not promise universal exactly-once effects or duplicate an observation while pretending it is the original sample.

Cancellation stops future scheduling and dispatch, marks pending work, and reconciles anything already in flight. It cannot undo an effect that has already happened. Restoring an earlier field generation never rolls the external-effect journal back into ignorance of that effect.

### Storage and lifetime

The [whole-machine performance design](CASSI-PERFORMANCE-DESIGN.md) consolidates the proposed CPU/GPU residency, shared brain queue, asynchronous communication, and incremental persistence around these commit and recovery rules. Its adaptive coordination uses the existing field owner, while the entity's resource and effect records retain their execution responsibilities.

Use incremental or shared immutable storage where the existing representation supports it; do not duplicate the complete field and transcript for every thought without accounting for the cost. Set separate limits for live field capacity, native caches, immutable evidence, and historical checkpoints. Reserve publication space before launching a large operation. If storage cannot support an atomic commit, stop admitting expensive work and retain the recoverable incumbent.

Retention preserves active dependencies, approved recovery points, source evidence supporting retained knowledge, and effect reconciliation records. Garbage collection works from explicit reachability and user retention policy; it does not delete research evidence merely because it is old or ignored by Git. User-requested forgetting must invalidate derived knowledge and projections consistently, with any required operational retention made explicit.

Model context is compressed or rebuilt from authorized committed information when necessary. A summary cannot silently discard an unresolved contradiction, permission constraint, or pending effect. Lossy context reduction and exact native restoration are different operations.

## 16. Scientific work from sources to conclusions

### Complete source access

A mission grants access to complete authorised libraries, not a handpicked sequence of excerpts. The researcher navigates directories, full-text indexes, citations, source links, code symbols, tables, and datasets. Context limits determine which material is presented in a particular brain turn; they do not impose an arbitrary limit on what the program may study.

Extend the current lossless source-segmentation and exact-evidence patterns to files, papers, archives, databases, and permitted public-web acquisition. Retain original bytes and version identity; extraction stores page/table/byte spans and its own method/version. A parsed number links to its original source. Missing or unreliable extraction is visible, not silently filled by model recall.

Source discovery and source comprehension are different operations. Structural indexes locate material; field-held relations and the brain interpret it. An uninspected document cannot be reported as read because its title was indexed. Different sources agreeing is not independent support when they repeat the same underlying dataset.

### Questions and explanatory work

Research can proceed through deduction, observation, simulation, software construction, literature synthesis, or combinations. The brain may suggest hypotheses, analogies, mathematical models, coordinate changes, and methods. The field relates those proposals to the program and retains the distinctions that matter.

Each consequential scientific claim refers to its assumptions, scope, supporting artifacts, and contrary evidence. Distinguish an exact result under assumptions from an empirical finding and from a promising hypothesis. Confidence is a useful assessment, not a substitute for a derivation or observation. Corrections propagate to dependent claims, plans, and reports rather than erasing the original evidence.

Choosing an experiment includes deciding whether it is worth doing. The researcher can try a bound, limiting case, inexpensive simulation, or alternative dataset before a costly reconstruction. It can decide that a measurement cannot discriminate the explanations and choose another. It is not required to force every investigation toward confirmation of CassiTheory.

### Calculations, code, and experiments

An executable investigation records the question, competing expected outcomes, method assumptions, source/input versions, code identity, command or instrument request, relevant environment, output artifacts, and interpretation. This is operational research data, not a requirement for a new frozen-verdict document.

Use existing numerical, symbolic, statistical, and simulation tools where suitable. Construct missing analysis code in the program's workspace; check its behavior on the actual use and appropriate boundaries. Preserve units, coordinate conventions, precision, sampling/selection effects, and uncertainty. An unsupported dependency becomes an explicit installation request or an alternative method, not a fabricated result.

Long runs publish partial progress and recoverable artifacts when supported. A killed run, empty output, or successful process exit is classified from the actual result. Numerical convergence and controls are selected for the scientific question. Domain-specific CassiCosmos and CassiTheory rules still apply when their machinery or documents are used.

A second Qwen critique can expose mistakes; it is not a second experiment. Prefer an exact checker, independently implemented calculation, original source, or appropriate world observation when it can resolve the question. Preserve unresolved disagreements when nothing yet decides them.

### Methods and cumulative work

A successful approach can become a field-held method with typed inputs, applicability, procedure/artifact reference, known failure conditions, and provenance. The program can reuse, specialise, compose, or revise it as later work demands. Code artifacts remain immutable versions; the field retains their meaning and selection.

Research-method development is attached to useful work: for example, building a robust table parser, deriving a reusable uncertainty transform, or constructing a solver required by several investigations. The result enters service through the same execution and authority boundary. Do not substitute a new benchmark of general learning for using the method.

or resumes only those distinct member homes. Fixed host handles index live
sessions but contain no learned roles or allocation strategy. The explicit
standalone organism launcher can retain its own root-opening mode; the entity
deployment uses attachment exclusively.

The existing director is the sole background scheduler for this deployment.
Extend it to service field-selected root/member obligations through their
respective serialized owners. Member work can invoke its own field and a
reserved brain/tool lane without starting another autonomous root director.
Root and member publication are separate commits; a returned member result
becomes attributed evidence at the root, never a transaction that writes both
fields at once. Shutdown stops dispatch, reconciles workers, closes borrowed
Hive handles, and closes only owners the service actually owns.

Extend the existing six record families with these typed views:

| View | Existing families | Required content |
|---|---|---|
| Investigation | `Obligation`, `Value`, `Binding` | Mission/question, parent, goal and input versions, alternatives, prerequisites, authority/allocation references, selected method, and continuation |
| Instrument or procedure | `Program`, `Assessment` | Typed inputs/outputs, units/frame/time, support conditions, effect bounds, dependencies, cost, applicability, and actual use history |
| Explanation | `Value`, `Binding`, `Assessment` | Conditional relationships, assumptions, predictions, competing interpretations, support, counterexamples, and unresolved distinctions |
| Translation | `Binding`, `Program`, `Assessment` | Source/target meanings, executable correspondence, preserved distinctions, lost information, conditions, and observed or derived scope |
| Collaboration | `Obligation`, `Binding`, `Event` | Question owner, member roles and requests, input versions, dependencies, attributed contributions, and waiting conditions |
| Experience and appraisal | `Event`, `Assessment` | Source identity/version, actual outcome, goal/object context, prediction comparison, appraisal-program version, and situated significance |
| Regulation episode | `Event`, `Obligation`, `Program`, `Assessment` | Trigger, chosen response, expected useful change, actual operations, delayed outcomes, attribution, and resource cost |
| Teaching and development | `Program`, `Assessment`, `Obligation` | Portable method, recipient prerequisites, adaptation, later use, corrections, and proposed improvement |

These are views and payload roles, not new databases or independent state
machines. Semantic identity, version, source roots, scope, and epistemic status
remain explicit. Exact artifacts and transport journals stay external where
appropriate; learned meaning, relevance, credit, and unresolved cognitive work
remain in the responsible field.

The programmable companion's Section 4 refines these families into
`RepresentationProgram`, `WorldProgram`, `DesignProblem`, `ReasoningStudy`,
`InstrumentProgram`, `ConstructorProgram`, and `WorkspaceBinding` views.
Program-valued construction, hypothetical world state, search frontiers,
reasoning-study progress and learned method applicability remain in the
responsible field. Client projections and exact immutable artifacts do not
become independently adaptive copies of that state.

The public path remains the current entity program API, shared session entry,
and owner `submit`/`invoke`/`advance` machinery. Extend their typed projections
and existing capability descriptions rather than introduce a parallel research
API. Host indexes may locate records, but cannot supply learned answers when
the field is unavailable.

### 19.3 One complete learning and research cycle

1. **Orient.** Relate admitted experience to commitments, expectations,
   prerequisites, resources, and object/project affect. Reuse unfinished work.
2. **Form the question.** Retain what is unresolved, why it matters, which
   alternatives remain, and what observation or deduction could distinguish them.
3. **Choose an approach.** Select local work, specialist delegation, method
   adoption, or deeper study. An instrument or missing prerequisite can itself
   become a child investigation under the same mission and allocation.
4. **Construct.** Use field programs and attributed brain contributions to
   develop a representation, runnable explanation, measurement, instrument,
   plan or composition. A missing construction method may itself be developed.
   Preserve alternatives, source meanings and explicit missing information.
5. **Predict and prepare.** Bind expected discriminating outcomes, applicable
   assumptions, exact inputs, method versions, and effects before execution.
   This is ordinary retained research state, not a frozen-protocol document.
6. **Execute.** Dispatch only through an available authorized capability.
   Internal hypothetical branches can derive consequences but cannot dispatch
   real effects or manufacture observations.
7. **Admit and assess.** Archive the actual result, admit it once through the
   owner, compare it with expectations, and classify missing/invalid results
   separately from valid negative findings.
8. **Learn and appraise.** Update the applicable understanding and the event's
   goal-conditioned significance. Assess any earlier regulation response whose
   awaited consequence is now available.
9. **Continue or collaborate.** Refine the question, request help, use another
   representation, pursue a consequence, or wait for a named requirement.
10. **Compose and teach.** Turn useful work into a conditional reusable method,
    representation or constructor; let recipients bind it to their meanings,
    adapt it and return actual use experience.
11. **Consolidate and improve.** Abstract recurrent structure while retaining
    exceptions. Investigate encountered reasoning obstacles and use their
    consequences to improve inquiry, teaching, regulation and construction.
    Keep exact computational optimization distinct from a newly assessed method.

Every step uses the existing program lifecycle and durable action phases.
There is no second host cursor for intellectual progress. An interrupted tool
operation resumes from its retained intent/result/admission state; a suspended
thought resumes from its field continuation. Waiting does not count as another
experience, reset the allocation, or discard the unresolved question.

### 19.4 Constructed observations and predictive explanations

The physical research branch exposes reusable capabilities rather than a
permanent sequence of transport, circulation, and winding stages. Existing
campaigns remain named methods and retained evidence. The learned lifetime
continues while physical worlds can be reset or varied independently.

The construction vocabulary composes:

- selection of regions, paths, surfaces, entities, and time intervals;
- sampling, differences, derivatives, integrals, fluxes, and correlations;
- transformations of frame, orientation, scale, and temporal alignment;
- object tracking, validity masks, uncertainty, and comparison operators;
- authorized interventions and observation-contingent continuations.

Each operation retains units, coordinates, time, boundary conditions, support,
resolution, and numerical conventions. A valid zero, an unsupported
measurement, an absent observation, and failed execution are different outcomes.
Constructed measurements cannot read hidden simulator answers. Selection rules
used in a comparison are identified and applied consistently; choosing
different regions because they yield preferred outcomes changes the question
and cannot silently inherit the old interpretation.

Acquire bounded snapshots or windows, use inexpensive summaries to guide
detail, and reuse immutable captures when a new analysis can answer the
question. Reinterpreting a capture supplies another derivation, not another
independent physical sample. New privileged sensors or host kernels enter the
existing engineering and authority boundary; ordinary compositions run as
field programs over available primitives.

Explanations predict conditional effects, delays, persistence, and failure
conditions rather than only assign outcome labels. The learner may revise the
variables, history, decomposition, and timescale of a model. Exact derivation,
empirical support, useful approximation, and open hypothesis remain distinct.
An accessible observation that cannot distinguish explanations is a reason to
change the investigation, not force a conclusion.

An executable explanation binds its represented state, transition/readout
procedures, initial and boundary conditions, uncertainty, numerical regime and
forecast history. It can run in a private branch and be compared with other
explanations against the same identified observations. Resolution and
approximation choices remain visible; simulated agreement is a derived result,
not another independent observation. External simulation retains its own
adapter identity, effect policy and continuation limits.

Inverse design develops from an admitted desired outcome, horizon, constraints
and admissible interventions. The field chooses or constructs the search or
control method and owns its candidate frontier. Candidates carry their model
dependencies, predicted readouts and constraint disposition. Search exhaustion,
missing information and proved infeasibility within the represented problem
remain distinct; a method cannot improve its score by silently changing the
goal, constraints or observation rule.

A candidate becomes a proposed world action through existing authority.
Observed consequences revise the explanation and subsequent design decisions.
This connects discovery of persistent structures with learning how to create
and maintain them when supported by the actual investigation. The companion's
Section 14.2 supplies the execution and state rules.

### 19.5 Translation and collective synthesis

Different members may represent the same situation geometrically,
numerically, causally, or procedurally. Retain a correspondence as an executable
proposal with explicit roles, assumptions, and information loss. Test its
consequences through actual use or a valid derivation. Similar words or
correlated vectors do not establish equivalence, and a lossy mapping is not
silently invertible.

**Representation decision.** A translation is a canonical semantic `Program`
with `program_role = procedure`, using the existing typed semantic-program
payload. A `Binding` carries `source_representation_ref`,
`target_representation_ref`, `mapping_program_ref`, `role_bindings`,
`units_frames_time`, `preserved_distinctions`, `lost_information`, `conditions`,
and `assessment_refs`. Each reference includes identity, kind, and content
version; foreign contributions also bind their origin owner and artifact.
Inverse use requires its own applicable mapping or a checked invertibility
claim. The receiving owner validates and admits the proposal; its subsequent
use or derivation supplies support.

Representation development can construct the source and target descriptions
themselves: entities, roles, operations and, where useful, a domain language.
The representation's executable observation mappings preserve its grounding,
losses and unresolved distinctions. Parsers, interpreters and transformation
methods are ordinary admitted programs. New meanings create versions and
explicit mappings; they never silently redefine the evidence attached to an
older representation. The companion's Section 14.1 specifies this acquisition
and migration path.

Collective synthesis constructs a new executable whole from partial
contributions. The coordinator retains the problem decomposition, interfaces,
compatible assumptions, dependency versions, unresolved holes, and expected
behavior of the composition. Members can work on those holes without receiving
private material irrelevant to their assignment.

A composed controller, for example, may combine structure description,
tracking, disturbance prediction, and intervention selection. Individually
useful components do not prove that the loop is stable or useful; assess the
actual composition and retain its failure conditions. A successful composition
can become a parameterized `Program` whose components and interruption points
remain accessible for later repair.

The synthesis view retains `question_ref`, `component_refs`, `translation_refs`,
`port_bindings`, `guards`, `unresolved_holes`, `expected_consequences`,
`program_ref`, and `contributor_refs`. It references a procedure rather than
introducing another interpreter. A partial composition remains nonexecutable
where a required hole is unresolved. The question owner's field selects
components and mappings; fixed validators check compatible types, units,
effects, and resource bounds before ordinary owner dispatch. The result
Assessment depends on the exact composition and actual outcome, not only on
the individual component assessments.

The composition strategy is itself learnable: how to decompose, which
interfaces to construct, when to seek an alternative, and how to integrate
disagreement. Fixed validators check types and effects; they do not secretly
choose the answer-bearing decomposition and credit that invention to the field.

Specialist instruments have typed representation-aware ports, applicability,
effects, state and suspension requirements. Symbolic, geometric, numerical and
neural instruments can therefore contribute to one procedure without hiding
their origins or differing numerical guarantees. Each composed program retains
its own assessment; successful components do not establish a useful whole.

Constructors are acquired procedures that return candidate programs,
representations or further constructors. Their products retain construction
lineage, source dependencies and unresolved requirements, and pass ordinary
admission before execution. A constructor cannot grant its products authority
or access to private captured state. Hive teaching can carry these ways of
building instruments alongside completed instruments; recipients retain
delegate/adopt/study choices and return actual use outcomes. The companion's
Section 14.4 defines the shared callable and higher-order execution boundary.

### 19.6 Curriculum and access to distributed capability

The field chooses among four routes:

| Route | When useful | Retained result |
|---|---|---|
| Delegate | Relevant expertise is available elsewhere and local acquisition has limited immediate value | Attributed result, its applicability, dependency on that member/capability, and actual collaboration outcome |
| Adopt | A reusable portable method already meets a recurring local need | Compatible program, bound local meanings, use assessment, and any specialization |
| Study | Understanding is needed to adapt, explain, combine, or invent | Prerequisite work, acquired representations/methods, and subsequent use |
| Develop | No schedulable member owns the typed method a committed composition requires | Bounded primitive method owned and selected by one member, the composition's actual test result, and the outcome recorded against that member's provider history |

Receiving correct output is not acquiring the specialist's competence;
importing program bytes does not establish grounded applicability. The
organism can nevertheless use distributed expertise immediately. If a
specialist becomes unavailable, the dependency is visible and the question
can be reassigned, studied, or retained as waiting.

A parked gap whose required typed interface no schedulable member owns is not
a dead end. The organism exposes it as a development opportunity bound to one
member, the exact source symbols the composition already supplies, the
remaining work bound, and the requested output meaning. The brain proposes one
bounded primitive method over those symbols and declares its assumptions and
uncertainty. The selected member's field owns and selects that method under its
own agenda rather than receiving an installed answer; the live composition then
tests it by producing the missing output. A method that completes its waiting
continuation is a recovered capability; a proposal that does not compose leaves
the gap parked with the failure recorded. Both outcomes are observed provider
outcomes, so later development favors the members whose constructions actually
ran.

Selection considers mission progress, uncertainty that can be resolved,
learning potential, prerequisite/unlock value, retention, underexplored
approaches, actual cost, and situated affect. Preserve a bounded opportunity
for unfamiliar methods. Repeated surprise from noise and repeated work on an
inaccessible problem are not automatically valuable.

Prerequisite relationships reveal shared bottlenecks: an instrument or
translation may make several investigations tractable. The field learns these
relationships from ensuing work. Do not reduce the portfolio to lesson counts,
positive findings, agreement, or a single emotional reward. Hard eligibility,
resource ceilings, and service fairness remain external constraints.

### 19.7 Working groups, teaching, and shared adoption

Temporary groups form around questions. Investigator, builder, critic,
integrator, and teacher are changing assignments informed by context and
experience, not permanent species of agent. Members can request expertise
directly within scope. The root maintains purpose and relevant dependencies
without mediating every intermediate exchange.

A shared workspace is a coordinated set of field-owned question and
contribution references. It is not a mutable host blackboard containing the
only copies of the group's understanding. The question owner retains the
integration view; each member retains its own work and attributed received
material. Stale contributions remain evidence but require reassessment against
current dependencies.

Keep two exchange paths distinct:

- **Working collaboration:** questions, partial results, candidate methods,
  concerns, counterexamples, and hypothetical interpretations. Each retains its
  status and can inform further authorized inquiry without becoming an
  installed skill or established claim.
- **Durable teaching:** applicable portable instruments, representations,
  explanations, investigative methods, and regulation programs. Use existing
  Hive review, bundle publication, recipient binding, and adoption mechanisms.
  Recipients return adaptations and actual use outcomes.

**Delegation sequence.** Use existing `HiveQuery`/`HiveOffer` objects to
transport availability and declared applicability. `QueryRouter.match` may
filter or shortlist; its current static reliability/work score is not the
organism's learned provider-selection policy.

1. The requesting field retains an `Obligation` with `request_id`,
   `question_ref`, `requested_role`, exact input references, desired result
   meaning, visibility, dependency versions, and allocation/authority refs.
2. Admitted offers bind provider lineage, candidate/procedure references,
   declared prerequisites and cost, and supporting evidence or explicit unknowns.
   The requesting field evaluates applicability using its own contextual
   experience and retains its selection.
3. An assignment Event binds request, accepted offer, provider, arguments,
   result requirements, operation ID/digest, and reservation. The provider
   admits it into its own owner under its own policy, then accepts, declines,
   or reports a precise unmet requirement. An offer alone is no execution.
4. The director schedules the accepted local obligation. The member's field
   develops and executes the work through ordinary capabilities; immutable
   outputs and an attributed response retain the assignment and source lineage.
5. The requester admits the response once and checks its current question,
   input versions, and output requirements. It can use the result, request a
   correction, adopt an applicable program through normal policy, or open
   deeper study. These produce distinct records and consequences.
6. Later use returns an attributed Assessment or adaptation to the provider.
   Changed evidence invalidates dependent live use; it does not overwrite the
   original response or erase the provider's independent history.

The current query/offer and lesson machinery supplies components of this path,
not an already implemented autonomous delegation service. Shared bundle
generation advances only through reviewed publication/adoption, never through
an ordinary request, offer, tool call, or speculative exchange.

Preserve the current population policy for an experiment that claims shared
adoption: independent member review, required quorum, exact portable bundle,
and adoption by the declared cohort at the common generation. An ordinary tool
result or tentative discussion is not such a claim. Import-disabled or
incompatible required members make that campaign's adoption incomplete;
neither policy is silently overridden.

A common generation identifies accepted shared material, not identical member
beliefs or competence. Disagreement can expose different evidence, meanings,
applicability conditions, predictions, or instrument defects. Resolve the
relevant difference or retain conditional alternatives. Protect independent
investigation before exposing conclusions when independence matters.

Reuse `SkillPolicy`: export-enabled within the already authorized hive and
visibility scope, independent import/inbox and application controls, and
preservation of each existing member's settings. Publishing to a new destination
or disclosing private material is not implied by shared learning.

### 19.8 Affect throughout the cognitive cycle

Affect is a field-owned appraisal of what an experience means for goals,
understanding, agency, resources, and relationships. It supplies situated
significance, not another independent observation or a measure of truth.
[Field design Section 37](CassiFI/FIELD-INTELLIGENCE-DESIGN.md#37-field-owned-affect-and-regulation)
specifies its records, dimensions, operating semantics, and learning.

The same episode can obstruct a practical goal while improving understanding.
Keep outcome desirability, information gained, controllability, uncertainty,
effort, and cooperation distinguishable. Emotional names summarize patterns;
the organism need not select a single label before acting.

| Cognitive use | Consequence of an applicable regulation program |
|---|---|
| Attention and memory | Select relevant evidence, prior turning points, counterexamples, or recovery methods while preserving source meaning |
| Construction and deliberation | Adjust permitted search breadth, alternative representations, work quantum, or when to refine a branch |
| Inquiry | Request a discriminating observation, inspect an instrument, or seek contrary evidence |
| Cooperation | Delegate a specific obstacle, request a second perspective, offer help, or change the division of work |
| Consolidation | Execute a useful abstraction/rehearsal/teaching procedure or preserve a consequential exception |
| Continuation | Persist, change approach, reduce concurrent work, wait, or disengage with the obligation retained |

These are actual selected operations with consequences, not mood adjectives
added to prompts. The active brain receives the grounded causes, goal, and
selected strategy as workspace content. The starting modes are a bootstrap
repertoire; learned programs can compose richer regulation within the same
capability and allocation boundaries.

Members share attributed concerns and opportunities with their causes.
Recipients appraise their significance locally rather than import another
member's mood. Repeated shared-source reports do not create independent
support. Trust concerns a member or method in a context and remains separate
from scientific support and permission.

Local fast responses, sustained project dispositions, and slower tendencies
coexist. A setback in one investigation need not dominate the whole hive.
Reappraisal may change the meaning of an event without counting it again.
Useful regulation is assessed by subsequent work and learning; changing a mood
score or generating a reassuring narrative cannot certify success.

### 19.9 Consolidation, credit, and correction

Consolidation discovers what several episodes are instances of. Factor useful
common structure into guarded programs, retain discriminating examples and
counterexamples, and keep access to the detailed episodes. Preserve source
independence when many members learn from the same event.

An episode can improve world understanding, measurement, explanation,
procedure, collaboration, and regulation. These are different derived uses of
one experience. They do not multiply its evidential weight. Delayed outcomes
may support several contributions without uniquely identifying their causal
shares; retain that uncertainty.

When a real episode leaves an important question about the reasoning method,
the field can open a scoped causal study of that computation. It names the
restorable predecessor, changed component, measured outcome and conditions held
fixed. Complete state includes relevant model history, sampler/RNG state and
identified environment inputs. Removing an already-used source from a prompt
does not remove its influence from derived knowledge or model memory; the
study must reconstruct the relevant predecessor or retain a narrower claim.

Compare actual computational consequences under the declared conditions.
Dependency traces and model self-descriptions alone do not establish cause.
Missing feedback, nonmatching replay and an uninformative comparison retain
their status. Internal contrasts can revise applicability and regulation
without pretending to observe hypothetical external consequences or uniquely
divide interacting contributions. The original world event is admitted once,
replayed effects remain inert, and study costs are charged. These are useful
investigations within ongoing work, not a learning-qualification requirement.

Consolidation can turn recurrent reasoning into a guarded executable method,
including the signs that deeper work is required. Retain source episodes,
important exceptions and correction dependencies. Exact compiler lowering
preserves the selected computation under its declared equivalence conditions;
an acquired shortcut or approximation is a separately assessed method.
Complete cost includes construction, checking, exceptional paths and recovery.
Benefit is useful downstream work under the retained result requirements,
not shorter traces or more lessons. Sections 14.3 and 14.5 of the programmable
companion specify these studies and simplification paths.

Adaptive usefulness, recipient needs, context-sensitive trust, and expected
cost remain in the fields that use them. A shared ledger can expose immutable
projections but cannot become a replacement learned policy. Negative findings,
instrument repairs, and avoided mistakes can be valuable contributions even
when they produce no positive scientific result.

Correction follows typed dependencies through explanations, methods,
translations, appraisals, pending work, and exported lessons. Stop new dependent
use, notify affected recipients, and revise or quarantine affected uses while
preserving unrelated knowledge. Historical observations and actual effects
remain historical facts; correcting an interpretation does not undo them.

### 19.10 Runtime, authority, and interaction

Use the existing director for wakeups and durable work, the owner for adaptive
commits, and the capability broker for effects. Persistent members can be
scheduled from retained homes without one permanently busy process each.
Allocate another learner when sustained independent experience is useful;
use temporary workers for ordinary calculations and source reads.

Charge source acquisition, brain use, construction, unsuccessful search,
simulation, teaching, review, storage, and recovery to the responsible root
allocation. CPU/read-only work can proceed concurrently. Reserve actual GPU
capacity; preserve one windowed Godot runtime and serialize incompatible brain
and simulation work. Suspension reconstructs the declared semantic/native
continuation rather than discarding the research lifetime.

**Execution accounting decision.** Extend the existing host execution journal
with nonadaptive reservations keyed by `reservation_id`, mission, owner/member,
work-order identity, resource class, cap, measured consumption, lease/fence,
and settlement status. Parent and child allocations reference the same
mission account. Duplicate delivery of one result settles one operation, not
another charge or another learning event.

The broker checks capacity and fixed fairness among eligible field-selected
work. The root/member fields retain predicted cost and scientific relevance;
the journal records actual use. Lease expiry fences late publication but does
not prove a process stopped or release a possibly occupied GPU. Observe or
reconcile the actual worker/device before reallocation. These shared leases,
portfolio accounting, and member scheduling are required extensions, not
capabilities claimed for the current director.

Private evidence, uncertainty, authority, and pending effects survive
summarization. Learned urgency cannot enlarge a grant. Generated field programs
use the bounded regional machine; generated host code remains unavailable for
unattended execution until the declared containment or explicit uncovered-scope
authorization is present. Construction, installation, and external publication
are separate actions.

Extend the current program/state/event projections to show: the current
question and why it matters; participating members and dependencies; completed
findings and their evidence; selected strategy and its grounded affective
context; acquired/adapted methods; resources and waiting conditions. Reports
explain useful changes in understanding rather than present a mood score or a
count of learning events as progress.

The user can guide priorities, inspect causes, pause a program/member,
change existing sharing settings, and approve an exact consequential action.
Routine inspection remains read-only. A request to discuss or design the
upgrade does not start the ongoing mission or change the user's permissions.

The shared live research workspace makes these interactions object-linked.
The user can point to a structure, equation, interval or source passage; propose
a relationship; hold named features fixed; and request a comparison through
the same program. Admitted annotations distinguish a reported experience,
suggested interpretation, constraint and desired outcome. A suggestion becomes
a scoped investigation rather than automatic confirmation of its content.

Views retain units, coordinates, source references and versions. They show
assumptions, predictions, observed outcomes and unresolved alternatives
together, with provisional and committed states distinguished. A stale
selection requires an explicit compatible rebind or separate branch; reopening
a view is read-only, and replay cannot repeat an experiment or learning event.
The user can continue, revise or teach from the result without transferring
ownership to the client. The companion's Sections 14.6 and 17.1 specify the
frontend and revision-bound API extensions, including authorization and recovery.

### 19.11 Upgrade continuity and recovery

The accumulated organism is the upgrade input. A new implementation does not
replace it with blank root/member fields or rerun the completed physics
curriculum to manufacture a new lifetime.

1. Retain an identified source/runtime and field checkpoint for every affected
   owner, plus pending work, dependency versions, sharing settings, allocations,
   and independent effect journals.
2. Quiesce affected publication boundaries and reconcile in-flight operations.
   Preserve immutable completed results for later interpretation.
3. Migrate semantic payloads, program references, and compatible continuations
   explicitly. Preserve lineage, episode identity, provenance, and unsupported
   or unknown values; do not invent new appraisal dimensions for old experience.
4. Publish a compatible source/field pair through the existing immutable
   generation mechanism. Unrelated members need not lose their independent
   working state; incompatible work waits with its pinned predecessor.
5. Resume from the appropriate program/action phase. Historical experience,
   imported lessons, and old regulation outcomes are not admitted again as new
   learning. Rebuild transient views from the migrated field.
6. On failure, retain the recoverable incumbent and candidate evidence. A
   rollback preserves actual effects and any newer evidence requiring explicit
   re-admission or reconciliation. A runtime unable to decode newer adaptive
   state preserves that state rather than silently dropping its learning.

**Migration mechanism.** Prepare a content-addressed migration manifest with
one row per affected owner: lineage/home, predecessor checkpoint and digest,
old/new runtime closure and schema/profile identities, candidate checkpoint,
record/reference mapping, continuation disposition, policy/configuration refs,
allocation and effect-journal cursors, and validation disposition. Keep
runtime/schema generation distinct from Hive bundle common generation.

Quiescence occurs at each owner's publication boundary after fencing new
dispatch. For a local cohort that must change together, prepare every required
row before atomically publishing a cohort manifest that names the complete
compatible set. The supervisor activates that set in the identified runtime;
it does not hot-replace Python modules inside the old process. An incomplete
preparation leaves the prior active manifest. Unaffected or explicitly
compatible members can remain on their existing runtime with declared
compatibility.

Preserve a state that the incumbent cannot decode as an immutable opaque
checkpoint together with its original runtime closure, evidence, and journals.
Mark that member/continuation unavailable to the incompatible runtime; do not
guess a projection or reset it. Recovery opens the compatible predecessor or
an explicitly validated migration. Useful newer experience is reconciled by
identity and explicitly admitted where valid; unknown effects are not rerun.
Per-owner publication pointers alone are insufficient to claim this multi-owner
upgrade, so the cohort manifest and supervisor resolution are part of the build.

Method-level development can use a distinct member branch. Accepted lessons
return through normal teaching; rejected implementations can still leave useful
diagnoses or methods. Source installation and schema migration remain
engineering operations, not privileges earned by a favorable self-assessment.
