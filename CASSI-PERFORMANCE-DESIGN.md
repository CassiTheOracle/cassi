This document is a whole-system **target design** for performance work across Cassi's continuing field-owned mind, live pretrained brain, execution devices, communication, and persistence. It assembles the performance ideas into one architecture and an order for operational implementation. The existing owner, regional computer, research residency and organism, circulation, Hive, native runtime, method interfaces, and entity remain the ownership and adaptation machinery. ## Whole-machine architecture

Cassi is one continuing mind whose work can occupy many lightweight scoped working fields, one shared live pretrained brain, and durable fields/programs that acquire reusable responsibilities. A working field may be temporary or persistent, generalist or specialized through experience; it need not be a separate process or model copy. Sparse selection by relevance, expected contribution, uncertainty, and cost directs attention, while retaining coupled numerical or causal semantics wherever the operation requires them.

Different workers may learn at different rates and maintain locally scoped state, while cognition within one owner still follows that owner's declared operator, dependencies, and publication rules. Multiple rates or eventual convergence do not license unsynchronized writers or imply that strongly coupled regions can be processed as independent sequences. Independent Hive owners remain distinct minds and exchange attributed methods and evidence through existing collective machinery.

The adaptive field owns what matters, how concerns and methods develop, which work is valuable, and how acquired communication and organization improve. Host execution owns exact physical capacity, fixed device behavior, authenticated external effects, transport mechanics, and publication. A single owner remains authoritative for each mutable field and its published candidate. Many workers may compute concurrently; only valid dependency-aware successors can be adopted.

```text
                    one field-owned continuing mind
   priorities / methods / working fields / organism / continuations
            │ semantic queue, Need/Send/Subscribe intent
            ▼
    communication field ───────► CPU-resident control and local lanes
            │                     ├─ native workers / hash / storage
            │                     ├─ shared resident Qwen brain
            │                     └─ GPU field, vision and expert work
            │                              │
            └──── exact versions, dependencies, acknowledgments ────┘
                         │ results, evidence, completion
                         ▼
       one owner validates dependencies and publishes successor
                         │
       RAM / VRAM / NVMe / HDD residency and durable recovery
                         │
       measured outcomes improve methods, topology, routing, hot sets
```

This flow is an integration target: some pieces exist, and the connections and performance behaviors described in later sections require implementation. Each activity has an exact continuation and dependency closure, so it can make progress, wait, resume, or be cancelled without inventing a second planner or ownership layer.

## Hardware, locality, and working-set shape

The queried host configuration (24 Sep 2026) is Ryzen 7 7800X3D, 8 physical cores / 16 SMT threads, 32 KiB L1 data and 32 KiB L1 instruction plus 1 MiB L2 private to each core, and 96 MiB shared L3 with 64-byte cache lines. RAM is 2×16 GiB DDR5-5800. GPU is Radeon RX 7900 XTX, advertised with 24 GB GDDR6, 96 MB Infinity Cache, and 960 GB/s peak memory bandwidth per AMD specifications ([CPU](https://www.amd.com/en/products/processors/desktops/ryzen/7000-series/amd-ryzen-7-7800x3d.html), [GPU](https://www.amd.com/en/products/graphics/desktops/radeon/7000-series/amd-radeon-rx-7900xtx.html)). The drives are C: ADATA SX8200NP 480 GB NVMe, E: Crucial CT1000P1SSD8 1 TB NVMe, and D: WDC WD140EMFZ 14 TB SATA HDD. These are separate CPU/GPU memory and storage tiers, not interchangeable cache.

A default regional field has 9×16,384 = 147,456 words: 1,179,648 bytes (1.125 MiB) in its current float64 carrier, or 589,824 bytes (576 KiB) as lossless u32 machine words. Sixteen current-plus-successor fields occupy 36 MiB in float64 or 18 MiB in u32; 32 occupy 72 MiB or 36 MiB. These totals exclude other state, scratch, the OS, the brain, and concurrent tasks. Even the single 1.125 MiB field exceeds one core's 1 MiB private L2. The aggregate 8 MiB L2 is not shared; tile/cache cohorts around private L2 and shared L3 accordingly. Hardware caches manage themselves: placement and affinity are useful hints, not a way to reserve or pin L3.

Place frequently interacting hot regions and their successors on cache-local cohorts, use soft affinity and locality-aware stealing, and balance a cohort's full working set against other active tasks. Store compact contiguous data; choose AoS, SoA, tiling, and SIMD across compatible rows from actual access patterns. Avoid false sharing and repeated allocation. Count scratch, temporary copies, queued successors, staging and other workers in the budget. Set one physical-core thread budget across native workers, hashing, model, vision and storage; SMT is a measured choice rather than a free second core. Python's GIL makes native hot loops important for CPU-parallel numerical work.

## CPU and native compact field execution

The CPU remains an always-available responsive self: it receives control, reports status, coordinates queues and communication, and advances independent CPU work while a device is busy. Reserve enough capacity for those functions and make device yield bounded, with continuations retained exactly. The reserve is part of admission, not a separate mind.

Regional machine words are canonically u32, losslessly represented, with an explicit versioned layout/ABI. Current float64 carriers can be replaced only with an explicit migration preserving exact values and identity; numerical fields keep their required precision. No global float32/float16 shortcut is implied. If a layout change alters canonical bytes or hashes, migrate digest identity explicitly. Exact SHA/digest identity remains canonical. The native runtime computes it with the CPU's SHA extensions (`sha256rnds2`/`sha256msg1`/`sha256msg2`, selected by a CPUID probe, portable compression otherwise) in [`CassiFI/native/field-runtime/protocol.hpp`](CassiFI/native/field-runtime/protocol.hpp); both routes produce the identical FIPS 180-4 bytes. A physical cache key cannot replace content identity.

Hot paths should operate on compact typed records and bounded changed-region/page work. Replace full image copies, deep copies, and JSON queues where they materialize unchanged content; reuse buffers and choose staged, undo, or copy-on-write successors according to atomicity. Extend paged staging, descriptors, and caches already present. Avoid revalidating, re-encoding, re-hashing, or serializing unchanged data without weakening exact source, effect, or publication guarantees. [`CassiFI/cassi_field_regions.py`](CassiFI/cassi_field_regions.py) contains the regional profile, `step_field` image-copy/JSON-queue/deep-copy behavior, paged staging, chunked u32 persistence, and relevant caches; [`CassiFI/cassi_field_computer.py`](CassiFI/cassi_field_computer.py) contains wrappers. Current checked batching/caches are useful machinery, so this design does not presume every byte is always rescanned.

Changed-page reuse saves movement and persistence. The current `state_sha256` still binds profile/shape and complete float64 image bytes: after a changed state, compute that exact digest over the reconstructed logical image. Cached per-page hashes cannot yield the same flat SHA-256; adopting a tree digest would require a versioned identity migration. Reuse clean backing and serialize dirty pages without claiming that exact whole-image hash work disappeared.

## Resident GPU, shared brain, and two scales of sparse work

### GPU fields and reusable execution

Keep hot numerical slices, field state, weights, per-sequence KV or recurrent caches, and reusable activation arenas resident in packed GPU slots. Transfer only needed inputs and changed outputs; retain recoverable raw evidence. A field GPU batch requires real arithmetic kernels: the native Vulkan field word-op path executes set/fill/copy and add-constant/compare-set compute on the device, exports changed pages, and verifies exact canonical digests with a CPU oracle; it remains a u32 word executor, not a generalized arithmetic field executor ([`CassiFI/native/field-runtime/`](CassiFI/native/field-runtime/)).

Follow the [swarm's private candidate and publication lifecycle](CASSI-PROGRAMMABLE-SWARM-DESIGN.md) on the device. A published version's page map and applicable model-history roots remain immutable while one owner candidate writes copy-on-write pages. Export touched pages, ordered results and exact continuation for owner validation and durability; after committed acknowledgment, promote the candidate's device map and reuse clean backing in the next epoch. The Vulkan backend holds a committed and a pending image per owner: `commit_candidate` promotes the pending image only when its base is the published predecessor and its content is the accepted successor, and `discard_candidate` releases it on refusal, cancellation or failure ([`CassiFI/native/field-runtime/vulkan_backend.hpp`](CassiFI/native/field-runtime/vulkan_backend.hpp)). An unpublished result can never become the next authoritative input. The last durable owner state remains recoverable if the device is lost.

Group compatible work by exact model and source identity, backend, stage, layer, operator, profile, shape, dtype, expert, and dependency boundary. Use bounded padding/masks, asynchronous cohorts, and fusion when they preserve every required operation. Independent work needs no global barrier. Record/reuse command sequences where the backend supports them. Preserve neural-field intervention semantics and their actual order by compiling the required interventions into the device execution; performance policy cannot omit them.

Avoid needless stage round trips, activation allocator churn, repeated vision dequantization, and device→host→device exchange around ROCm intervention sites. Keep validated immutable objects resident. [`CassiFI/programs/model/qwen_vision.py`](CassiFI/programs/model/qwen_vision.py) currently has a CPU projector with repeated dequantization and a limited block cache; ROCm intervention sites include CPU round trips. These are concrete optimization seams, not permission to alter intervention semantics.

### Shared Qwen and neural mixture

Use a shared resident Qwen weight bank with multiple sequence contexts, continuous batching, immutable shared weights/code, and isolated mutable model/field history per activity. Manage chunked prefill separately from decode cadence: foreground response has a reserve, while compatible background sequences fill spare capacity. Prefix and continuation reuse keys must include exact model, source, token sequence, relevant field influence/state, method, and backend compatibility. Prompt text equality alone is insufficient. Existing token-scoped membrane epochs already span remaining stages in a token; the opportunity is persistent tensors/caches/arenas across stages and tokens, not new token epochs. Narrow dependency tracking may avoid unrelated epoch invalidation, but a changed relevant dependency invalidates the continuation. Preserve each activity's exact mutable history.

A foreground request can dispatch at the next available safe point without waiting to fill a batch. Bound non-yieldable prefill/decode segments; add compatible background work only while its staging and memory charges fit the foreground reserve. The useful batch size depends on both aggregate throughput and arrival-to-response latency.

Qwen neural expert grouping is distinct from sparse cognitive working-field selection. Group matrix work by the model's actual, field-influenced expert choices; prefetch or reuse resident experts using the existing learned policy. Do not replace actual routing with a performance-selected expert. [`CassiFI/programs/model/expert_learning.py`](CassiFI/programs/model/expert_learning.py) selects/observes residency and can prefetch, but does not replace model routing. Batch only when same-owner or strongly coupled dependency semantics allow it. The sparse field queue chooses cognitive concerns; neural expert execution groups the arithmetic selected by Qwen.

Three native decode paths exist today. The native program path decodes in token runs: one owner admission advances up to `NATIVE_TOKEN_RUN_MAX = 8` tokens inside the native runtime, stops at the first stop token, and records each token as its own continuation row under the run's owner operation and generation. Each request records the sampler the native C API executes (canonical greedy form, float32 temperature), so a rebuild from owner history reproduces greedy and categorical runs token for token ([`CassiFI/programs/model/runtime.py`](CassiFI/programs/model/runtime.py), [`CassiFI/cassi_programmable_swarm.py`](CassiFI/cassi_programmable_swarm.py)); [`CassiFI/verify_native_token_runs.py`](CassiFI/verify_native_token_runs.py) checks that against a real GGUF for greedy, stop-token and categorical sampling, on the first round and again with every round rebuilt from owner history. Compatible native tasks share one weight bank through a group host: [`CassiFI/native/field-runtime/llama_backend.hpp`](CassiFI/native/field-runtime/llama_backend.hpp) creates one context with `n_seq_max` and `n_ubatch` equal to the group capacity, evaluates every row's stage in one fused pass per round, and lets rows join and leave between rounds; the swarm forms these cohorts in `_service_native_group_cohort` and serves a task alone in a single-sequence context (`n_seq_max=1`, `n_ubatch=1`) when no compatible partner exists or the group cannot advance. The resident brain's staged path (`resume-resident-model`, one owner round per graph stage so field interventions apply at their layer) is the third path and remains one sequence per context. One round of that path now covers a prompt block of up to `RESIDENT_PROMPT_BLOCK_MAX = 8` consecutive positions: the executor still runs every stage of every position, each position still opens its own membrane epoch and closes its own field-owned cycle and epoch with its own receipts and ordered exchange, and a position whose head sampled ends the round, so generation keeps one round per token while the round's publication, task reservation and native image import happen once per block. [`CassiQwen/cassi_field_brain_entity.py`](CassiQwen/cassi_field_brain_entity.py) has a one-brain `FairBrainScheduler` with foreground burst 3; [`CassiFI/cassi_field_owner.py`](CassiFI/cassi_field_owner.py)'s `run_to_boundary(_batch_to_token=True, block_positions=...)` retains one membrane epoch across remaining token stages, and native `DeviceEpochState` can span a token.

### Field acquisition of Qwen graph work

The implemented first graph acquisition is expert synthesis in CassiFI's resident Qwen executor. An owner-held method learns the combined routed and shared expert output from native stages, applies exact source, route, field, and input-support guards, and can replace that output while preserving the next hidden-state continuation. A real Qwen3.6 GGUF stage skipped 28 native expert projections when its method fired; an unsupported route ran those projections and supplied new training evidence. This observation establishes graph work omitted at that site; end-to-end speed and answer quality require separate measurement.

The native fork carries the same observe/replace contract for all four specialist sites in [`CassiQwen/native/llama.cpp/src/models/qwen35moe.cpp`](CassiQwen/native/llama.cpp/src/models/qwen35moe.cpp): the combined MoE output, the whole recurrent branch with its successor recurrent state, a full-attention block's output together with the K/V rows later tokens attend to, and the output head as full-vocabulary logits (`llama_cassi_context_graph_site_candidate_set` in [`CassiQwen/native/llama.cpp/include/llama-cassi.h`](CassiQwen/native/llama.cpp/include/llama-cassi.h)). A candidate binds exact source, sequence and position, the predecessor native-state digest, owner generation and an input-support guard; a refused candidate leaves the ordinary graph running and reports its reason. On this host's Qwen3.6-35B-A3B, an attention-memory candidate at layer 3 omitted four native operators, an execution-choice candidate omitted the output-head projection, and stale-predecessor and position-mismatch candidates were refused. The dense `qwen35.cpp` graph serves the same sites: at a ready boundary a 24-layer Qwen3.5-0.8B Q4_0 model reported 25 sites — recurrent dynamics on its linear-attention layers, attention memory on layers 3, 7, 11, 15, 19 and 23, execution choice at the output head — every one supported ([`CassiFI/verify_native_graph_site_boundary.py`](CassiFI/verify_native_graph_site_boundary.py)). Every descriptor names the loaded architecture, and owner-held methods deploy natively on both architectures. Sites act at decode boundaries: the preflight accepts the one unserviced token of the sequence's log and names it at `history - 1`, a freshly created sequence holds the whole prompt unserviced and is refused with `native_sequence_not_at_single_token_boundary`, so the swarm holds that round to one ordinary token and an admitted method can act from the second token on.

The shared brain can teach Cassi to perform selected computations inside its own forward pass. One continuing CassiFI owner holds four initial specialist working regions: **expert synthesis** learns the combined routed and shared expert contribution; **recurrent dynamics** learns state transition and output for the hybrid linear-attention branch; **attention and memory** learns relevant history and bounded retrieval/compression; **execution choice** learns when to draft, use a supported early exit, select a bounded output set, or request the ordinary Qwen operation. These are acquired programs and scoped numerical state in the existing regional field, organism and Hive method machinery, not four new model services or one learner per layer/expert. Specialties share supported methods across layer positions using explicit layer, operation and context inputs. The field can revise their scope or organization as measured work accumulates.

For this host's current Qwen3.6-35B-A3B GGUF, the metadata declares `qwen35moe`, 41 blocks including one NextN block, a 2,048-wide hidden state, 256 routed experts and eight selected experts. Thus ordinary generation crosses 40 trunk layers. The GGUF file is about 16.04 GiB on disk; GPU residency, KV/recurrent caches, activation arenas and other device users determine actual room for field batches. These are model-specific facts, not a fixed shape for the graph-learning interface. [`CassiFI/programs/model/qwen_executor.py`](CassiFI/programs/model/qwen_executor.py) names observation sites across attention, recurrence, experts, residuals and output. [`CassiQwen/native/llama.cpp/src/models/qwen35moe.cpp`](CassiQwen/native/llama.cpp/src/models/qwen35moe.cpp) executes the actual routed/shared experts and hybrid attention and hosts the four native graph sites. [`CassiFI/programs/model/ngram_learning.py`](CassiFI/programs/model/ngram_learning.py)'s bounded head readout is a separate acquired operation, not an implementation of these graph replacements.

**One graph-site contract.** An invocation names the exact model/source and tokenizer identity, architecture/backend, sequence and token position, stage/layer/operator, input/output tensor layout and arithmetic profile, predecessor field generation, native KV/recurrent state root, intervention order, dependency versions, method generation and applicability guard. The field program reads an immutable view and returns a typed candidate: output tensor and any required successor native state, scoped field delta, supported range, cost estimate and the precise graph operations proposed for bypass. The runtime admits only declared shapes, bounded work, compatible numerical profiles and a valid predecessor; an ineligible site executes Qwen normally with its reason recorded. Training targets and GPU execution caches are derived from owner-held program generations; they cannot become a second adaptive parameter authority.

**Executable representation and learning.** Each specialist owns a versioned typed program and bounded numerical regions in the continuing field. A small fixed kernel vocabulary lifts the available hidden/state inputs into declared field coordinates, evolves a bounded resident field, applies gated/low-rank combinations, reads out the site tensor, and, for recurrent methods, constructs the complete successor state. A layer/operation identifier and declared context let one program share acquired structure across layers; unsupported model architectures and dimensions require an explicit new method generation. Native CPU/GPU kernels implement those fixed operations and cache compiled schedules by program, model, profile and dependency identity; coefficients, applicability and unfinished learning remain owner-held field state, while activation and gradient buffers are disposable scratch. Teacher-site output/state disagreement proposes coefficient updates, and later native continuation and actual task outcomes correct both the program and its applicability guard. The owner admits one bounded successor after checking prior skills, resource cost and downstream effect. This vocabulary can grow by adding a missing bounded primitive without placing a second learned network or optimizer state beside the field.

The same site supports **observe**, **assist**, **replace** and **propose**. Observe captures Qwen's input/output and downstream effect without changing the pass. Assist adds a declared correction and records its cost, including the full Qwen operation that still ran. Replace cuts the specified native subgraph, inserts the field output and advances *all* state that subgraph would have changed, or refuses the replacement. Propose supplies a tentative suffix or choice to a native verifier; accepted prefixes and rejected tails retain separate field/model histories. A task names the verb for each specialist; when it names none, an admitted expert-synthesis or recurrent-dynamics method deploys and attention memory and execution choice stay off. The swarm's native dispatch, the resident executor and the owner's ticket builder read that one rule (`configured_mode` in [`CassiFI/programs/model/graph_site.py`](CassiFI/programs/model/graph_site.py)). A positive field influence, changed logits, and saved graph work are distinct observations. Routing/prefetch optimization continues to follow the model's actual field-influenced choices on paths whose router runs; a learned router or expert replacement is a separately identified semantic intervention with its own downstream checks.

Begin with the **combined MoE output**, including routed and shared contributions. Replacing only the small router leaves the expensive expert matrices in use. Next target the **whole recurrent branch**: incoming projections, convolution and recurrent update, returned vector and exact successor state must form one coherent replacement. Swapping just the recurrence while still running its large projections offers little saving. Attention-memory methods must preserve causal masks, positions and the state required by later tokens; an early exit must provide a valid downstream/head interface and avoid the bypassed layers; a candidate-set head must name the support it can emit. Speculative field drafts use Qwen verification under the real sampler and intervention history. Unsupported contexts go through the ordinary graph. Each candidate's bypass boundary determines which model weights, state bytes, transfers and kernels are genuinely avoided.

**Acquisition and acceptance.** Capture a native site's actual inputs, outputs and state transitions on ordinary authorized work, with exact predecessor and source identity. A specialist predicts the site result from inputs available *before* that result, learns from measured disagreement and later task outcomes, and retains both useful scope and failure cases in the owner field. Train the site mapping and its applicability decision together; compare downstream tokens, task correctness and errors outside the learned support, including prior skills, before adopting an operating route. Shadow and assisted results are useful learning evidence while still charged for Qwen's work. The owner commits a method generation only after its declared checks and dependency closure succeed; later failures can withdraw that generation while preserving the predecessor and evidence. This is operational qualification of changed inference, not a new campaign to establish whether Cassi learns.

**Batched execution without split ownership.** One resident Qwen weight bank supplies teacher observations for several independent candidate field views or sequence histories. Start by measuring 1/2/4/8 compatible views, with four candidate views as an initial scheduling target rather than a capacity promise. Group by model/source, site/layer, shape, dtype, backend, sequence-state profile and intervention dependencies; masked or padded rows keep their own position, owner, field generation and acceptance identity. One model observation may be reused across candidate views only when its exact native predecessor and all relevant field influences agree. Keep field tensors and Qwen captures in a resident GPU arena where the backend actually supports it; batch arithmetic kernels and compact owner deltas rather than full activation round trips. The native group host already fuses compatible sequences from one weight bank, and a row whose owner history carries graph-site interventions stays out of a group (`_native_group_incompatibility`), so graph-site teaching still runs one sequence per context. Extend the group host and the graph-site ABI together so rows with their own site programs can share a fused round, retaining a CPU route only when its full cost and semantics are known.

The host resource executor admits Qwen weights, per-sequence cache/field state, candidate successors, scratch, transfers and foreground reserve as one peak device budget. Background teaching fills available safe quanta; a foreground request never waits for a four-field group to fill. Independent candidates can compute in parallel against immutable predecessor views, while the existing owner stages and publishes compatible successor deltas in causal order. Reject stale work, retire cancelled buffers only after device fences, and persist a committed field/native pair before exposing its accepted token continuation. A failed replacement cannot continue from Qwen cache or recurrent state belonging to another branch. Do not average distinct candidate states or merge independent Hive owners to manufacture one learner.

**Measure useful displacement.** Per site, record teacher/candidate identity, guard firing and refusal, output/state error, downstream task outcome, native subgraph actually skipped, model-weight bytes touched, device time, transfer bytes, peak VRAM, rejected draft work and committed field work. At the whole-request level, compare useful completed work per second, foreground arrival-to-useful-response and pause latency (including tails) with the Qwen baseline at matching context and quality. Profile warm and cold paths and shared-GPU contention; a shadow/assist route may improve an answer while adding compute, and a replacement counts as a speed gain only when end-to-end time and resource use improve within the mission's quality and latency allowance. Let the field learn which supported graph operation is valuable next from those outcomes; fixed host admission, external-effect authorization and publication rules remain intact.

### Backend selection and prediction

Choose CPU/Vulkan/ROCm kernels and contexts by whole-request cost and capability, including setup, copy, warmup, migration and residency. Retain supported persistent contexts and admit migration only when its complete cost and representation are known. Visual/transient contexts stay pinned until a real migration representation exists. Use hardware-supported vector/matrix kernels at precision matching error and semantic requirements. Avoid backend thrashing.

Field drafting runs today with exact target verification, and a draft round now costs one native pass. When a resident request samples, the owner-held drafting policy in [`CassiFI/programs/model/draft_learning.py`](CassiFI/programs/model/draft_learning.py) proposes up to eight tokens; [`CassiFI/programs/model/runtime.py`](CassiFI/programs/model/runtime.py) carries them on the run plan as `run.draft_tokens` under the run's own operation ids and pre-drawn sampler values, and [`CassiFI/cassi_programmable_swarm.py`](CassiFI/cassi_programmable_swarm.py) commits the whole round through one `verify_model_draft` call instead of one native head sample per token. The native runtime answers with one row per committed token shaped exactly like an ordinary step result, so the owner admits the round as consecutive one-token resumes in position order. The context checks the proposal's first token against its own exact-pipeline sample: on a match it verifies the rest of the draft in the same pass and commits the accepted prefix plus its own sample at the first divergence or a bonus token beyond the whole draft, and on a miss it commits that one ordinary token, so a round never spends a pass it cannot use. A row whose token is in the owner's stop set ends the round there, and the next dispatch reconciles the native cache with the owner's accepted history. Accepted prefixes and rejected tails remain separate histories that teach the policy, and each row keeps its own replay digest, stage-trace digest, sampler identity and stage counts, so a rebuild from owner history reproduces the round token for token. On the local Qwen3.5-0.8B, a three-token proposal that matched the target's chain committed four rows through one pass, a proposal diverging at its second token committed the matching head plus the target's own sample, and the fork's `llama_cassi_verify_draft`/`llama_cassi_verify_commit` ([`CassiQwen/native/llama.cpp/include/llama-cassi.h`](CassiQwen/native/llama.cpp/include/llama-cassi.h)) remain the one-pass verifier behind it. Predictions and preloads stay distinct from actual evidence; drafting is worthwhile only when total work and latency improve.

## Resource executor, async flow, and publication

Coordinate CPU workers, hashing, model, native field, vision and storage pools through one host resource executor. Admit work against physical cores/threads, RAM, VRAM, temporary and successor bytes, transfers, prefetch, and device-queue time. Include peak memory, display/vision/model contention, and foreground reserves. Cache footprint informs placement but is not a reservable hardware tier. `PhysicalAdmission` in [`CassiFI/cassi_field_residency.py`](CassiFI/cassi_field_residency.py) is that executor's admission: one fair owner-wide account of physical cores, RAM, VRAM, transfer and peak bytes, backed by the field's `ResidencyManager` and made global across callers by journal reservations. Background work cannot consume the foreground reserve (one physical core in the entity), while foreground work may use the whole budget. Owner numerical work, resident brain segments, swarm resident candidates and Qwen stage cohorts all lease through it; the hash, numerical and resident pools keep their own thread counts inside those leases.

Vulkan, ROCm, Godot and display work on this machine contend for the same physical GPU resources even when they have separate contexts and API budgets. Account their resident bytes, queues, compute and transfers together; zero-copy interoperability between APIs is an explicit capability to establish, not an assumed shortcut. Backend moves charge both source and destination until the old allocation can retire.

The existing field-owned brain/work queue connects semantic selection to deterministic physical batching. Its choices can consider urgency, concern, expected contribution, uncertainty, waiting age/fairness, cost, dependency, locality, context/expert reuse, and compatible batch opportunity. Bound waiting, admission and backpressure. Reserve foreground responsiveness, then let background work fill capacity. Do not put a new host planner between field-owned priorities and execution.

Extend the [regional queue's wait and liveness rule](CassiFI/FIELD-INTELLIGENCE-DESIGN.md) to transport and physical-resource waits. A blocked foreground `Need` lends bounded urgency to runnable prerequisites. Expose a closed wait cycle with no admissible producer, including one formed by reservations held across waits, as a blocked obligation. Park its continuation without holding a mutation lock or scarce candidate slot. The host preserves fixed completion and retirement capacity; the field owns the priority and next useful decision.

Pipeline independent phases: CPU prepare → GPU compute → CPU interpret/adopt → storage persist. Overlap them without oversubscribing cores or saturating the same memory bandwidth with competing work. Track critical-path unblock and bounded fairness; an independent result should not wait for unrelated slow work. Work submission carries immutable version and exact dependencies. Compute and I/O run outside long global locks; owner mutation and commit use short lanes. Each owner has one writable candidate epoch and one publication authority. Dependency closures permit unrelated changes to coexist. Stale successors cannot replace current state; useful late results can remain attributed historical evidence. Cancellation fences adoption while resources stay accounted until actual retirement. Preserve exact continuation/restart and external effect identity. Completion and retries must not replay settled effects.

Work, rest, sleep and wake can run at multiple rates. Numerical clocks, integration rates and communication cadence are separate. Strongly coupled regions synchronize where the operator requires it; approximate operators retain error bounds. Idle time cannot manufacture an outcome or freeze a coupled field merely because a worker rested.

[`CassiFI/cassi_field_owner.py`](CassiFI/cassi_field_owner.py) already provides durable `submit_numerical_work`, collect and cancel paths with scoped dependency closures and exact source bindings; [`CassiFI/cassi_research_organism.py`](CassiFI/cassi_research_organism.py) provides organism/working-field machinery and [`CassiFI/cassi_circulation.py`](CassiFI/cassi_circulation.py) feeds back spectral outcomes and eligible-work modulation. [`CassiFI/cassi_programmable_swarm.py`](CassiFI/cassi_programmable_swarm.py)'s mirrored-validation double execution is an opt-in branch, not all runs. Any future removal of duplicate validation must retain owner-accepted semantics and focused correctness, never suppress failures.

## Dedicated communication field

A communication field/program becomes the single logical place where workers express `Send`, `Need`, and `Subscribe`: exact object version, destination or method, urgency, dependencies, and completion identity. A worker submits intent and continues eligible independent work or retains a wait continuation. This is a target connection to current mechanisms, not an existing adaptive transport field.

Keep always-available control and coordination on the CPU; use compact native per-device queues/lanes for actual movement. The field learns routing, timing, grouping, locality, prefetch and compatible coalescing. Fixed native transport moves bytes, handles memory visibility/fences, and acknowledges exact versions. Urgent control/completion must remain serviceable while a brain or device is stalled. Do not serialize all payloads behind one central lock, invoke an LLM per packet, or require SQLite/fsync/document publication for each high-rate packet.

Bound pending-intent credits separately from admitted physical-work credits. A retry with the same operation identity, exact request digest and dependency versions joins its existing in-flight reservation and result; distinct compatible pure immutable requests may reuse that calculation while each receiver keeps its own admission and acknowledgment. Required events and external effects retain their separate identities. A parked waiter consumes bounded queue/continuation space rather than a GPU execution slot.

Persist intent and outcomes at owner commit boundaries where durability is required; transport indexes and queued physical work between commits may be rebuildable. Preserve source and operation IDs, causal order, receiver acknowledgment/adoption, retries, and duplicate-delivery semantics. Repeated delivery must neither repeat physical effects nor count additional learning. Coalesce only explicitly replaceable updates; retain required events and bounded backpressure/waits. High-rate movement and durable control records have different cadences.

Keep staging, KV/scratch, predecessor/successor pages and submitted work charged until their actual fences and references retire. Stop optional preload first under foreground pressure and retire reclaimable preload pages before essential working state. Limit submitted brain/device segments so urgent control and foreground work can run at bounded safe points. Cancellation fences adoption immediately, while cleanup and physical capacity return follow real retirement.

Device-local fences are local. Cross-device lifetime and ordering require owner-issued versions and dependency closure plus explicit runtime coordination; one process endpoint or one local fence cannot establish global coherence. Immutable shared data travels as references/copies; canonical field state has no unsynchronized independent writers. Hive carries attributed methods and evidence across independent owners; local CPU/GPU transport moves physical bytes. The current [`CassiFI/cassi_hive_collective.py`](CassiFI/cassi_hive_collective.py) defines `HiveQuery`/`HiveOffer`/`QueryRouter` (lines 1362–1432, 2729–2783) as host matching, and `MethodPort`/`MethodInterface`/`ExecutableMethod` (1435–1546) as portable programs with assumptions and preconditions. Hive control documents do not provide adaptive tensor transport.

Spectrum can carry measured affinity, receptivity and participation and modulate bounded eligible work. A semantic compatibility and authority check remains necessary. Do not map frequency to fixed resource or emotion formulas, or describe it as a private channel. Routing feedback includes transfer latency, bytes, congestion, receiver use, reuse and work unblocked; delivery alone is not correctness or scientific progress.

Attribute a routing choice to its request, bounded eligible alternatives, dependency versions and resource conditions. Admit useful receiver work once through the owner's identified outcome event when that later result arrives; leave unresolved outcomes unresolved and replay the admitted event rather than remeasuring it. Rehearsed alternative routes remain hypothetical until actually used. Measure routing against work unblocked and foreground response as well as bytes and delivery time, so a fast unused delivery cannot teach the field the wrong placement.

Move computation to resident data when the method and backend support it: a `Need` may reference an existing executable method; a GPU reduction can run beside a large array, compatible consumers can share an intermediate, and fan-out can send result references. Move small programs or continuations to resident inputs when exact state and backend semantics permit it. This avoids bulk movement and repeat calculation without weakening attribution or dependencies.

## Acquired responsibilities and collaboration topology

Performance develops through acquired field-owned responsibilities, not a fixed set of host policies. Reuse exact shared source parsing and verification, content-addressed prerequisite/result artifacts keyed by all applicable dependencies, immutable program/source pages, and copy-on-write working branches. Reuse acquired methods/instruments rather than repeating general brain reasoning; provide stable relevant context and remove unnecessary prompt content. Stop or rest work when its purpose settles.

An anticipation field learns likely next inputs, methods, experts and context from continuations; prefetch only within bounded spare resources and credit the prediction when later work actually uses it. A representation field chooses spatial, spectral, symbolic or reduced forms with explicit method, units, applicability and error, while keeping exact source recoverable. Reduced models and surrogates can dominate low-level throughput when applicable; observed outcomes correct the method. A method/compilation field notices recurrence and builds, combines, specializes or fuses executable procedures while retaining intervention/effect semantics, assumptions, guards, deoptimization and exact continuations. It checks outputs and cost. It can construct methods for constructing methods; its learning is not a closed menu. Platform or ABI changes are explicit migrations.

A teaching/method-sharing field finds compatible consumers and transfers the executable method with provenance, assumptions, evidence and corrections through existing collective/Hive channels. Shared-origin evidence retains one origin. A continuity/repair field watches obligations, waits, stale dependencies and stalled continuations; it reconstructs or resumes exact unfinished work, reconciles late results and unknown/completed effects, and does not replay settled effects or reset learned state. Small prediction/rehearsal branches may compare routes, methods or organizations against retained inputs while useful work continues within the mission resource share. Hypothetical results remain distinct from evidence about external outcomes. This is not a new learning-proof campaign.

Edge/perception fields interpret relevant changes near a sensor, application or data stream, pass compact observations and wake appropriate work. Acquired procedures avoid full-screen/full-source/model recomputation each tick. Viewers consume bounded, age- and coverage-described snapshots and decimated read-only readouts, not a whole-field synchronization per frame.

Topology itself can improve through repeated collaboration: communication observes an A→B→C pattern; an organizer co-locates or adjusts compatible membership; the method field constructs a reusable workflow; future work invokes it; outcomes revise both organization and method. Explicit programs govern branch, grow, merge and rest while preserving dependencies and unfinished obligations. Microfields contribute to one mind; independent Hive owners remain distinct. Existing owner/swarm/entity machinery is the substrate for this learned evolution, not an assertion that this full adaptive topology loop is implemented.

## Persistence, tiers, and observation

Jointly manage residency across CPU caches (hot windows), RAM (warm state, sources and standby), VRAM (resident dense work), NVMe (hot exact artifacts/checkpoints), and HDD (cold archive). Preallocate rings and pinned transfer staging when useful. Keep hot sets, successors, brain/vision allocations, and transfer staging inside a total peak budget. Async transfers require explicit visibility and fences. A visual/transient context remains resident until its state has a real migration representation.

Reserve predecessor, private successor, scratch, export staging and recovery headroom before dispatch. Track clean/reconstructible, dirty and fence-pinned pages by version. Evict reconstructible backing when its live uses have retired; export and checkpoint dirty authoritative state before a move that needs it. A cancellation or cross-device transfer retains page generations and both ends' resource charges until candidate, checkpoint and device-timeline uses retire and destination visibility is established.

Persist changed pages and append-only deltas where compatible with exact recovery; reuse descriptors and exact digest results for unchanged data. Pipeline compression, hashing and I/O without changing durability, atomic publication or restart semantics. Do not serialize/fsync whole state per kernel. Keep exact source/effect journals. Separate dataset compaction and prefetch from adaptive knowledge. [`CassiFI/programs/model/state_backing.py`](CassiFI/programs/model/state_backing.py) (453–772, 1256–1445) already hashes/writes/flushes/fsyncs new arrays and manifests, while reusing unchanged immutable arrays; content-addressed persistence exists. `prune` bounds every store to `retain_generations` (16) and `retain_bytes` (8 GiB) by default, always keeping `CURRENT`, the newest manifest and every digest the caller protects: it runs inside each durable save and after deferred publication, drops manifests outside that window, then deletes every backing no retained manifest references. A backing an open mapping still holds stays on disk and is reclaimed by the next pass, and a page whose backing a pass reclaimed is republished from memory under its unchanged digest, so live pages survive reclamation. If a retained manifest cannot be parsed, that call deletes no backings. The atlas history compacts separately at `CapacityLimits.max_history_bytes` (4 GiB) through `_compact_history_for` in [`CassiFI/cassi_field_owner.py`](CassiFI/cassi_field_owner.py). The store also saves a snapshot with `defer_publication`: the manifest and any array bytes no backing holds yet stay in memory, the rendering owner seals exactly one snapshot per publication, and `make_durable` writes that snapshot's manifest and new arrays before its fsync. Unsealed stage snapshots release their references when the last ticket for the stage transaction retires, so a token's stages cost one durable snapshot rather than one per stage. Any new state-history append/delta format must preserve exact resume semantics. In the Qwen executor, `_save_state` (739–809) reuses unchanged immutable arrays and passes the executor's deferral flag for ordinary stage snapshots. On the measured resident path each stage save now reuses the digest of an unchanged read-only array by identity (146,914 reuses in one 64-token-prompt request), skips re-stat of bytes already reserved for the sealed snapshot (75,272 reuses), and reads a manifest's page sizes from the immutable objects instead of restating every page; eviction publishes the exact bytes it drops, and a swept backing forgets its verified-digest claim, because a sealed manifest can still name either. The remaining per-stage cost is the canonical JSON digest each publication computes over stage requests and results and the durable writes themselves. A prompt block of eight positions pays that publication cost once instead of eight times: on the same 64-token-prompt request the block writes 11 manifests instead of 67, 901 durable blob writes instead of 3,346, and 565 durability syncs instead of 3,413, keeps the same 1,679 per-stage snapshot descriptors, imports the native field image 19 times instead of 131, and defers the bytes a per-token cadence would have pruned mid-block (nothing pruned inside the request against 1.06 GB), because a block holds its positions' epochs live until its one publication. State persistence must be described accurately alongside volatile model/vision state.

In particular, `visual_embedding_id` selects volatile snapshot dictionaries in [`CassiFI/programs/model/qwen_executor.py`](CassiFI/programs/model/qwen_executor.py); durable `SnapshotStore.save` is the other branch. Do not attribute the reported 41-minute visual episode to fsync. That executor uploads old K/V at 1187–1188 and downloads full updated K/V at 1588–1590 for each full-attention layer/token: two uploads and two downloads total, not twice each. Recurrent state has an analogous path. Those are concrete residency opportunities; measurement is needed to establish their contribution to an end-to-end episode.

Observe ordinary end-to-end work: foreground response, useful completion, queue waits, active/blocked time, lock holds, batch sizes, CPU/device work, bytes copied/checkpointed, cache misses, memory/evictions, expert hits, startup/warm cost, clocks, thermal throttling, page faults, drive latency and supported device engines. Distinguish reported utilization from critical-path diagnosis. Include transfer and resource waits as well as compute. Scale activities at 1/2/4/8 concurrent activities and appropriate batch sizes; stop increasing concurrency when useful throughput plateaus or foreground latency or memory worsens. Batching can improve total throughput; one-request latency depends more on fusion, residency and reduced coordination. Cache/VRAM capacity and PCIe/data movement may dominate; extra fields can hurt. Firmware, overclock, driver or permission changes are outside this design.

Compare useful completed work per second against measured foreground arrival-to-first-useful-response and pause/control latency distributions, including p95/p99 tails, on comparable workloads. Declare a latency allowance for an actual mission before increasing concurrent activities or batch size. Whole-request throughput gains that exceed that allowance trigger smaller quanta or admission, rather than counting only mean GPU utilization.

## Integrated work episode

A field-owned research program discovers an exact source revision and submits analysis with its continuation, source bindings, dependencies, concern, urgency and resource estimate. The queue selects that responsibility and wakes only relevant working fields. Shared content-addressed parsing is reused if every source and method dependency matches. An acquired representation method identifies a reduction of the large dataset with stated units and error while preserving the exact source. The communication field finds the method and input resident and sends a versioned `Need` for the reduced result; the CPU control lane acknowledges it while independent work continues.

The shared executor admits the work against physical cores, memory, VRAM, transfers, brain capacity and foreground reserve. CPU-native preparation tiles compatible regional work for private-L2 locality while Qwen can prepare context whose field and source dependencies are already satisfied, at the next safe point without waiting to fill a batch. A resident GPU cohort then performs the requested reduction beside its input; reduction-dependent Qwen reasoning waits for the owner's durable admission of that exact result. Each activity keeps isolated field/model history and interventions execute in their actual order. Neural expert batches follow Qwen's field-influenced routing. If any dependency changes, the affected continuation is invalidated; unrelated current work continues.

If an eligible acquired expert method is selected for a token, the graph-site invocation reads that activity's committed field generation and native predecessor, executes the field result in its reserved device slot, and omits the declared routed/shared expert work. Other sequences may continue through Qwen's ordinary experts in the same service; their own intervention and state histories remain separate. The owner accepts the field successor and the corresponding native continuation together before the token becomes visible. Ineligible contexts retain the ordinary path without losing the teaching evidence that explains the limitation.

The owner receives a result reference with exact source/method identity, device completion and dependency versions. It interprets and validates the private candidate in a short commit lane, then durably publishes exactly one successor. The committed device map becomes the next resident version while storage records changed exact state and required effects at the owner's durable boundary; unchanged immutable backing remains available. A cancelled device computation remains resource-accounted until retirement and cannot publish. A late valid result may be retained as attributed historical evidence without overwriting current state or replaying an effect.

The communication and continuity fields record actual receiver use, bytes, wait time, reuse, work unblocked and unresolved obligations. The organizer may later co-locate a demonstrated collaboration pattern or the method field may specialize the repeated workflow; they do not promote a delivery or a prediction into evidence of a real external outcome. Foreground response and useful completed work are observed throughout. This episode composes the design without assuming its target connections already exist.

## Implementation order and operational slices

These are whole slices with dependencies, not a rigid serial checklist. Independent source/state and scheduler/communication work can progress in parallel once interfaces and publication authority are explicit. Each implemented slice is exercised on its real changed path, including relevant cancellation/restart/resource-wait behavior and numerical/source correctness; no generic learning-proof campaign is required.

1. **Trace ordinary work end to end.** Attribute wall time, active/wait states, copies, bytes, device setup, source/model verification, memory, locks and useful completion. Establish a narrow cost trace without claiming a causal ranking from utilization or old episode durations.
2. **Compact single-activity residency.** Remove measured redundant copies/codecs/state materialization; reuse exact immutable source/model data and persist changed pages while recomputing the current canonical whole-image digest correctly. Keep one activity's hot tensors/contexts resident when the backend and migration representation support it. Carry a private changed-page candidate through owner validation and durable commit into the next resident version, with exact recovery after device loss.
3. **One physical resource executor and safe asynchronous communication.** Unify capacity/admission across CPU and device pools, including shared-adapter contention, foreground reserve and predecessor/successor peak bytes. Connect versioned intents, bounded credits, retry joining, wait-cycle and prerequisite urgency, local queues, acknowledgments, cancellation fences and short owner commits; preserve one publication authority and exact continuations.
4. **Shared multi-sequence brain and compatible device cohorts.** Add persistent Qwen sequence contexts, separate prefill/decode scheduling, compatible batching/fusion and real arithmetic field kernels. Bound non-yieldable segments so a ready foreground request can dispatch without filling a batch. Group neural expert math from actual model choices and validate at exact intervention ordering. Include CPU fallback/migration only when whole-request cost and semantics permit it.
5. **Acquire and deploy Qwen graph work.** Connect the existing site observations to one owner-held specialist method contract. Capture real expert inputs/outputs, learn the combined contribution and applicability, then execute a genuine expert bypass with correct native continuation and rollback. The same contract now covers recurrent state/output, attention memory and the output head natively; the run-level draft round verifies a whole proposal in one native pass, while depth decisions and the execution-choice site's draft choices join it as their full state and verification rules are implemented. Batch compatible candidate views within the shared brain's foreground and VRAM allowance, and measure both downstream quality and native work actually avoided.
6. **Connect field-owned adaptive locality and communication.** Let the existing queue and communication field learn from delayed actual receiver use and feed deterministic batching, hot-set/prefetch and compatible routing. Keep bounded waiting, fairness, exact delivery, and separate-device fence semantics; keep alternative-route rehearsal hypothetical until used.
7. **Extend acquired performance responsibilities.** Improve anticipation, representation/reduced methods, executable method construction and fusion, teaching, continuity/repair, revisable collaboration topology and carefully verified drafting as useful responsibilities emerge. Exact dependencies, guards, provenance and correction stay with the method; hypothetical branches remain distinguishable.
8. **Tune whole-machine scale from evidence.** Compare real work at 1/2/4/8 activities and appropriate batch sizes. Choose concurrency from useful throughput subject to declared foreground response-tail and control/pause latency allowances, memory and wait/copy costs. Report conditions and actual measurements; change platform/ABI layouts only through explicit migration.
